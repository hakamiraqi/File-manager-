# FileNest — نظام إدارة ملفات واستضافة ومشاركة (Laravel + Inertia + Vue + MySQL)

نظام إدارة ملفات وسحابة تخزين شخصية/جماعية مبني بالكامل على **Laravel 13** و **Inertia.js (Vue 3)** و**MySQL**، مستوحى في مجموعة مزاياه من أنظمة استضافة ومشاركة الملفات الجاهزة (مثل Veno File Manager) لكنه **كود مصدري مستقل بالكامل** كتب من الصفر لهذا المشروع — بدون أي اعتماد على كودهم المصدري أو ترخيصهم.

يوفّر النظام:

- مساحة ملفات شخصية لكل مستخدم (مجلدات فرعية غير محدودة، رفع/تنزيل/بحث/فرز).
- رفع الملفات الكبيرة بتقنية **التقسيم إلى أجزاء (Chunked Upload)** عبر HTML5، لتفادي حدود `upload_max_filesize` في PHP.
- **مشاركة الملفات والمجلدات** عبر روابط عامة، مع كلمة مرور اختيارية، تاريخ انتهاء صلاحية، حد أقصى لعدد مرات التنزيل، وإرسال الرابط بالبريد الإلكتروني مع رسالة مخصّصة.
- **سلة محذوفات** (Trash) مع استعادة أو حذف نهائي، وتنظيف تلقائي مجدوَل بعد مدة محددة.
- **تنزيل جماعي** لعدة ملفات/مجلدات كأرشيف ZIP واحد.
- **لوحة إدارة (Admin Panel)** كاملة: إدارة المستخدمين وحصصهم التخزينية، إعدادات عامة (اسم الموقع، الشعار، صورة الترويسة، تفعيل/تعطيل التسجيل الذاتي)، اختيار "سكن" (Skin) للواجهة من 12 نمط لون جاهز أو CSS مخصص، وسجل نشاطات كامل (Audit Log).
- دعم كامل للعربية والإنجليزية مع اتجاه صفحات تلقائي RTL/LTR.
- حصص تخزين (Storage Quota) لكل مستخدم قابلة للتخصيص من لوحة الإدارة.
- **نسخ (Copy)** للملفات والمجلدات (بالإضافة إلى النقل)، مع نسخ متكرر لكامل شجرة مجلد فرعي.
- **أربعة أدوار قابلة للتخصيص بالكامل** (مستخدم، محرّر، مساهم، زائر) عبر مصفوفة صلاحيات في لوحة الإدارة تتحكم بكل إجراء على حدة (عرض/تحميل/مشاركة/رفع/حذف/تسمية/نقل/نسخ/إنشاء مجلد...).
- **تسجيل دخول عبر Google وGitHub وLinkedIn (OAuth/SSO)** بالإضافة إلى البريد وكلمة المرور التقليديين.
- **تصفح كضيف بدون تسجيل دخول** لمجلدات يحددها المشرف كـ"عامة"، مع تحكم منفصل بصلاحيات العرض/التحميل للزوار.
- **رمز تحقق (Captcha)** رياضي بسيط أو **Google reCAPTCHA** على التسجيل واستعادة كلمة المرور وتنزيل الزوار.
- **حظر/سماح عناوين IP** (Blacklist/Whitelist) على مستوى الموقع بالكامل.
- **الرفع من رابط خارجي (Remote Upload)** مع حماية من هجمات SSRF (رفض الروابط الداخلية/الخاصة).
- **روابط مشاركة مختصرة (Pretty Links)** وخيار **"استخدام لمرة واحدة"** يُلغي الرابط تلقائياً بعد أول تنزيل.
- **إعدادات SMTP كاملة من لوحة الإدارة** (بدون الحاجة لتعديل ملف `.env`)، مع إشعارات بريدية قابلة للتفعيل لكل حدث (رفع، تحميل، دخول، مجلد جديد، تسجيل مستخدم).
- **قائمة امتدادات مسموحة/ممنوعة** قابلة للتعديل من لوحة الإدارة، فوق طبقة حماية أمنية ثابتة لا يمكن تعطيلها.
- **لوحة تحليلات برسوم بيانية** (رفع/تنزيل/مشاركة عبر الزمن) باستخدام Chart.js.
- **عدة مشرفين (Sub-admins)** بصلاحيات إدارية محدودة يحددها "المدير الرئيسي" (إدارة مستخدمين فقط، أو مظهر فقط، إلخ).
- **محرّر ترجمات** داخل لوحة الإدارة يسمح بتعديل أي نص في الواجهة لكل لغة، مع إمكانية إعادته للنص الأصلي.
- **بث فيديو/صوت مع دعم التقديم (Seek)** عبر HTTP Range Requests.
- **فهرسة محتوى المستندات للبحث**: استخراج النص من داخل ملفات Word وPDF وPowerPoint والنصوص تلقائياً عند الرفع، وربطه بالملف بحيث يجده البحث من محتواه الداخلي وليس فقط من اسمه — أشبه بفهرسة مكتبة أو دار نشر.
- **صور مصغّرة حقيقية (Thumbnails)**: تُولَّد تلقائياً عند الرفع للصور (دائماً)، ولمقاطع الفيديو ولأول صفحة من PDF عند توفر الأدوات الاختيارية على الخادم، بدلاً من الاكتفاء بأيقونة عامة.

> **ملاحظة مهمة حول المصدر:** لم يُنسخ أي سطر كود أو شعار أو علامة تجارية من "Veno File Manager" (منتج تجاري مدفوع). الكود بالكامل مكتوب من الصفر خصيصاً لهذا المشروع تحت اسم مختلف (FileNest)، واستُخدمت الملفات المرجعية (الوثائق، وهيكل الميزات) لفهم مجموعة المزايا فقط دون نسخ التنفيذ أو الهوية البصرية.

## 2. التثبيت خطوة بخطوة

اتبع هذه الخطوات بالترتيب تماماً على جهاز جديد لم يُشغَّل عليه المشروع من قبل.

### الخطوة 1: نسخ المشروع

```bash
git clone <رابط-المستودع>
cd Ibn_alqaim/filemanager
```

### الخطوة 2: تثبيت اعتماديات PHP (Composer)

```bash
composer install
```

سيقوم هذا الأمر بتنزيل وتثبيت Laravel وكل الحزم المستخدمة (Breeze، Inertia، Sanctum، Ziggy...) داخل مجلد `vendor/`.

### الخطوة 3: تثبيت اعتماديات الواجهة الأمامية (npm)

```bash
npm install
```

### الخطوة 4: إنشاء ملف البيئة `.env`

```bash
cp .env.example .env
php artisan key:generate
```

الأمر الثاني يولّد مفتاح تشفير التطبيق (`APP_KEY`) ويكتبه تلقائياً داخل `.env`.

### الخطوة 5: تعديل إعدادات `.env`

افتح ملف `.env` وعدّل القيم التالية حسب بيئتك:

```env
APP_NAME=FileNest
APP_ENV=production        # أو local أثناء التطوير
APP_URL=https://files.example.com

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=filenest
DB_USERNAME=filenest_user
DB_PASSWORD=كلمة_مرور_قوية_هنا

MAIL_MAILER=smtp          # مطلوب حتى تعمل ميزة "مشاركة عبر البريد الإلكتروني"
MAIL_HOST=smtp.example.com
MAIL_PORT=587
MAIL_USERNAME=user@example.com
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS="noreply@example.com"
MAIL_FROM_NAME="${APP_NAME}"

# إعدادات خاصة بنظام إدارة الملفات (اختيارية، لها قيم افتراضية):
FILENEST_DEFAULT_QUOTA_MB=5120      # الحصة الافتراضية لكل مستخدم جديد (ميغابايت)
FILENEST_MAX_UPLOAD_MB=2048         # أقصى حجم للملف الواحد (ميغابايت)
FILENEST_CHUNK_SIZE_MB=5            # حجم كل جزء أثناء الرفع المُجزّأ
FILENEST_TRASH_RETENTION_DAYS=30    # عدد أيام الاحتفاظ بالعناصر في سلة المحذوفات قبل حذفها نهائياً
```

> ملاحظة: قيم `default_quota_mb` و`max_upload_mb` قابلة للتعديل لاحقاً من **لوحة الإدارة → الإعدادات العامة** بدون الحاجة لتعديل `.env` أو إعادة تشغيل السيرفر — قيم `.env` تُستخدم فقط كقيم مبدئية أول مرة (تُنسخ إلى جدول `settings` عبر أمر seed).

### الخطوة 6: إنشاء قاعدة البيانات

راجع القسم [3. إعداد قاعدة بيانات MySQL](#3-إعداد-قاعدة-بيانات-mysql) بالتفصيل، ثم عد إلى هنا.

### الخطوة 7: تشغيل الترحيلات (Migrations) والبيانات الأولية (Seed)

```bash
php artisan migrate --seed
```

هذا الأمر سيقوم بـ:

1. إنشاء جميع الجداول (`users`, `folders`, `files`, `shares`, `settings`, `activity_logs`, ...).
2. إدخال الإعدادات الافتراضية في جدول `settings` (اسم الموقع، السكن الافتراضي، اللغة، الحصص...).
3. إنشاء **حساب مشرف افتراضي** (راجع القسم التالي لبيانات الدخول).

### الخطوة 8: ربط مجلد التخزين العام (Storage Link)

مطلوب حتى تظهر صور الشعار وصورة الترويسة التي يرفعها المشرف من لوحة الإعدادات:

```bash
php artisan storage:link
```

### الخطوة 9: بناء ملفات الواجهة الأمامية

```bash
npm run build
```

### الخطوة 10: التحقق من الأذونات (على السيرفر فقط)

تأكد أن المستخدم الذي يشغّل خادم الويب (مثل `www-data`) يملك صلاحية الكتابة على:

```bash
chown -R www-data:www-data storage bootstrap/cache
chmod -R 775 storage bootstrap/cache
```

مجلد `storage/app/filemanager` هو المكان الفعلي الذي تُخزَّن فيه ملفات المستخدمين على القرص (منفصل عن `storage/app/public` الذي يستخدم فقط لملفات العلامة التجارية كالشعار).

بهذا يكون التثبيت قد اكتمل. 🎉

## 3. إعداد قاعدة بيانات MySQL

### إنشاء قاعدة البيانات والمستخدم

ادخل إلى MySQL:

```bash
mysql -u root -p
```

ثم نفّذ:

```sql
CREATE DATABASE filenest CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'filenest_user'@'localhost' IDENTIFIED BY 'كلمة_مرور_قوية_هنا';
GRANT ALL PRIVILEGES ON filenest.* TO 'filenest_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

- استخدم دائماً ترميز `utf8mb4` لضمان دعم صحيح للنصوص العربية وأسماء الملفات التي تحتوي على رموز تعبيرية (emoji).
- إذا كانت قاعدة البيانات على خادم منفصل، غيّر `'localhost'` إلى عنوان IP الخاص بخادم التطبيق، وعدّل `DB_HOST` في `.env` تبعاً لذلك.

### التحقق من الاتصال

```bash
php artisan migrate:status
```

إن ظهرت قائمة بالترحيلات بدون خطأ اتصال، فإعداد قاعدة البيانات صحيح.

## 4. تسجيل الدخول لأول مرة

بعد تنفيذ `php artisan migrate --seed`، يتم إنشاء حساب مشرف تلقائياً ببيانات الدخول التالية:

| الحقل | القيمة |
|---|---|
| البريد الإلكتروني | `admin@filenest.test` |
| كلمة المرور | `password` |

**الخطوات:**

1. افتح رابط الموقع في المتصفح (مثال: `https://files.example.com/login`).
2. أدخل البريد وكلمة المرور أعلاه.
3. **غيّر كلمة المرور فوراً** من: القائمة العلوية → **الملف الشخصي والإعدادات** → قسم "تغيير كلمة المرور".
4. (اختياري) عدّل اسم الموقع والشعار من **لوحة الإدارة → الإعدادات العامة**.

> لأسباب أمنية، لا تترك بيانات الدخول الافتراضية كما هي على أي بيئة إنتاج (production) فعلية.

### إنشاء مشرف إضافي لاحقاً

من لوحة الإدارة → المستخدمون → زر "مستخدم جديد"، واختر الصلاحية "مشرف". أو عبر Tinker:

```bash
php artisan tinker
```
```php
\App\Models\User::create([
    'name' => 'اسم المشرف',
    'email' => 'admin2@example.com',
    'password' => bcrypt('كلمة-مرور-قوية'),
    'role' => 'admin',
    'email_verified_at' => now(),
]);
```

## 5. تشغيل المشروع في وضع التطوير

في وضع التطوير تحتاج تشغيل عمليتين بالتوازي (في نافذتي طرفية منفصلتين):

**النافذة الأولى — خادم Laravel:**
```bash
php artisan serve
```
سيعمل الموقع افتراضياً على `http://127.0.0.1:8000`.

**النافذة الثانية — خادم Vite (لإعادة التحميل الفوري للواجهة أثناء التعديل):**
```bash
npm run dev
```

افتح المتصفح على العنوان الذي يظهره `php artisan serve`.

> إذا كنت تستخدم ميزة إرسال البريد الإلكتروني محلياً بدون خادم SMTP حقيقي، اضبط `MAIL_MAILER=log` في `.env` لتظهر رسائل البريد في ملف `storage/logs/laravel.log` بدلاً من إرسالها فعلياً.

## 6. النشر على استضافة حقيقية (Production)

1. ارفع الكود إلى السيرفر (عبر Git أو FTP لملفات المشروع كاملة عدا `node_modules` و`vendor`).
2. نفّذ على السيرفر:
   ```bash
   composer install --optimize-autoloader --no-dev
   npm ci && npm run build
   cp .env.example .env   # إن لم يكن موجوداً، ثم عدّله كما في القسم 2
   php artisan key:generate
   php artisan migrate --seed --force
   php artisan storage:link
   ```
3. اضبط جذر الخادم (Document Root) في Nginx/Apache على مجلد **`public/`** فقط (وليس جذر المشروع).
4. فعّل التخزين المؤقت للإعدادات والمسارات لتحسين الأداء:
   ```bash
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache
   ```
   > تنبيه: بعد تشغيل `config:cache`، أي تعديل لاحق على ملف `.env` **لن يُطبَّق** حتى تُعيد تشغيل `php artisan config:cache`.
5. أضف مهمة الجدولة (Cron) المطلوبة لتنظيف سلة المحذوفات تلقائياً — راجع القسم [13](#13-المهام-المجدولة-scheduler--cron).
6. (يُنصح به) شغّل **قائمة الانتظار (Queue) Worker** حتى تُرسل رسائل مشاركة الملفات بالبريد الإلكتروني في الخلفية دون تعليق الطلب:
   ```bash
   php artisan queue:work --daemon
   ```
   ولضمان استمراره بعد إعادة تشغيل السيرفر، شغّله عبر Supervisor.
7. فعّل HTTPS (شهادة SSL) دائماً — الجلسات وملفات تعريف الارتباط الخاصة بالمصادقة تعتمد عليه.

### مثال إعداد Nginx مختصر

```nginx
server {
    listen 80;
    server_name files.example.com;
    root /var/www/filenest/public;

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";

    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }

    client_max_body_size 2100M; # يجب أن يكون أكبر من FILENEST_MAX_UPLOAD_MB
}
```

> **مهم جداً بخصوص الرفع المُجزّأ:** رغم أن النظام يقسّم الملفات الكبيرة إلى أجزاء صغيرة (5 ميغابايت افتراضياً) لتفادي حدود PHP، إلا أن `client_max_body_size` في Nginx (أو `LimitRequestBody` في Apache) يجب أن يبقى أكبر من حجم الجزء الواحد على الأقل، ويُفضّل ضبطه ليتسع لأكبر ملف مسموح به فعلياً لتفادي أي تعارض.

## 8. دليل استخدام إدارة الملفات (للمستخدم)

بعد تسجيل الدخول، ستجد نفسك مباشرة في صفحة **"ملفاتي"** (المسار الرئيسي `/dashboard`)، وهي الواجهة الأساسية لإدارة الملفات.

### 8.1 التنقل بين المجلدات

- انقر **نقرة مزدوجة** على أي مجلد للدخول إليه.
- شريط **المسار التفصيلي (Breadcrumbs)** أعلى الصفحة يعرض المسار الحالي بالكامل بدءاً من "ملفاتي"، ويمكنك النقر على أي جزء منه للعودة إليه مباشرة.

### 8.2 إنشاء مجلد جديد

1. اضغط زر **"مجلد جديد"** في شريط الأدوات العلوي.
2. اكتب اسم المجلد في النافذة المنبثقة.
3. اضغط **"إنشاء"**.
4. إذا كان الاسم مستخدماً بالفعل داخل نفس المجلد، سيضيف النظام تلقائياً لاحقة مثل `(1)` لتفادي التعارض.

### 8.3 رفع الملفات

1. اضغط زر **"رفع ملفات"** واختر ملفاً أو عدة ملفات معاً، **أو** ببساطة اسحب الملفات من جهازك وأفلتها داخل منطقة الملفات (Drag & Drop) — ستظهر منطقة تظليل زرقاء تدل على إمكانية الإفلات. يمكنك أيضاً إفلاتها مباشرة فوق مجلد فرعي معيّن لرفعها داخله مباشرة دون الدخول إليه أولاً.
2. تُقسَّم كل عملية رفع تلقائياً إلى أجزاء صغيرة (Chunks) خلف الكواليس، لذا يمكن رفع ملفات كبيرة جداً دون التأثر بحدود حجم الطلب في PHP، وتظهر نسبة تقدّم كل ملف بشريط تقدّم حقيقي في لوحة "جارِ الرفع" أسفل يمين الشاشة (تماماً كما في Veno File Manager).
3. **إيقاف مؤقت واستئناف**: بجانب كل ملف قيد الرفع زرّ إيقاف مؤقت (⏸) يوقف الرفع فوراً دون فقدان أي جزء مرفوع بالفعل، وزرّ استئناف (▶) يكمل من حيث توقّف بدلاً من إعادة الرفع من الصفر. زر الإلغاء (✕) يوقف الرفع نهائياً ويحذف الأجزاء المؤقتة من الخادم.
4. **استعادة تلقائية لأجزاء الشبكة الفاشلة**: إذا فشل جزء واحد بسبب انقطاع مؤقت في الشبكة، تتم إعادة محاولته تلقائياً (حتى 3 مرات) دون تدخّل المستخدم قبل إظهار أي رسالة خطأ.
5. **الاستئناف بعد إغلاق الصفحة أو تعطّل المتصفح**: إذا أُغلقت الصفحة أو أُعيد تحميلها أثناء رفع لم يكتمل، يظهر عند الرجوع تنبيه أصفر بأعلى الصفحة بعنوان الملف غير المكتمل مع زر **"استكمال"** — بالضغط عليه واختيار الملف نفسه مجدداً، يتعرّف الخادم على الجزء الذي وصل بالفعل (حسب الاسم والحجم والمجلد) ويكمل رفع الأجزاء الناقصة فقط، دون إعادة رفع ما تم إرساله سابقاً.
6. بمجرد اكتمال الرفع، يظهر الملف تلقائياً في قائمة الملفات دون الحاجة لتحديث الصفحة.

### 8.3.1 رفع مجلد كامل

بجانب زر "رفع ملفات" يوجد زر **"رفع مجلد"** يفتح منتقي مجلدات المتصفح (يعتمد على خاصية `webkitdirectory` المدعومة في Chrome وEdge وFirefox) لاختيار مجلد كامل من جهازك بدلاً من ملف واحد أو عدة ملفات منفصلة.

- يُعاد إنشاء بنية المجلد الفرعية بالكامل داخل المجلد الحالي تلقائياً — كل مجلد فرعي (مهما كان عمقه) يُنشأ مرة واحدة فقط، ثم تُرفع كل الملفات إلى المجلد الصحيح المطابق لموقعها الأصلي على جهازك، عبر نفس بروتوكول الرفع المجزّأ (Chunks) المستخدم في رفع الملفات العادي (فقرة 8.3 أعلاه) — بما في ذلك شريط التقدّم لكل ملف.
- تماماً كإنشاء مجلد يدوياً، إذا كان اسم أحد المجلدات الفرعية مطابقاً لمجلد موجود بالفعل، يضيف النظام تلقائياً لاحقة مثل `(1)` بدلاً من دمج المحتويات — رفع نفس المجلد مرتين ينتج نسخة موازية له، وليس دمجاً في الأصل.
- لا يتطلب هذا الزر أي نقطة نهاية (endpoint) جديدة في الخادم: يستخدم نفس نقاط `POST /folders` (لإنشاء كل مجلد فرعي) و`POST /uploads/init|chunk|finalize` (لرفع كل ملف) المستخدمة في بقية النظام، لذا تنطبق عليه كل قيود الحصة التخزينية وأنواع الملفات المسموحة تلقائياً دون أي كود إضافي.

### 8.4 البحث والفرز

- استخدم مربع **البحث** أعلى يمين الصفحة للبحث عن ملف أو مجلد بالاسم (يبحث داخل كل مجلداتك، وليس فقط المجلد الحالي).
- استخدم القائمة المنسدلة **"ترتيب حسب"** لتغيير الفرز بين: الاسم، تاريخ الإضافة، الحجم.
- بجانب قائمة الفرز، يظهر دائماً عدد المجلدات وعدد الملفات في المجلد الحالي (مثل "3 مجلد، 12 ملف")، تماماً كما في Veno File Manager.

### 8.5 معاينة الملفات

انقر **نقرة مزدوجة** على أي ملف (غير المجلدات) لفتح نافذة معاينة سريعة:

- **الصور** (jpg, png, gif, webp...): تُعرض مباشرة.
- **الفيديو**: يُشغَّل داخل مشغل فيديو مدمج.
- **PDF**: يُعرض داخل الصفحة مباشرة.
- **الملفات النصية** (txt, json, csv): تُعرض كنص.
- لأي نوع آخر غير مدعوم للمعاينة، تظهر رسالة تطلب تنزيل الملف للاطلاع عليه.

يمكنك تنزيل الملف مباشرة من داخل نافذة المعاينة عبر أيقونة التنزيل أعلى النافذة.

### 8.5.1 عرض النص المستخرج من المستند

لأي ملف مفهرَس (PDF, Word, PowerPoint, TXT, MD, CSV...) — يظهر عليه شارة "مفهرس" كما في القسم 20.7 — يظهر أسفل نافذة المعاينة قسم قابل للطي بعنوان **"النص المستخرج من المستند"**. اضغط عليه لعرض النص الكامل الذي استخرجه النظام من المستند (وليس مجرد مقتطف بحث قصير)، وهو نص قابل للتحديد والنسخ. هذا مفيد خصوصاً لأنواع الملفات التي لا تدعم معاينة مباشرة (مثل Word وPowerPoint) — فيصبح هذا القسم وسيلتك الوحيدة للاطلاع على محتوى الملف دون تنزيله.

### 8.6 إعادة التسمية

اضغط زر النقاط الثلاث (⋮) بجانب أي ملف أو مجلد ← **"إعادة تسمية"** ← اكتب الاسم الجديد ← **"حفظ"**.

### 8.7 النقل بين المجلدات

طريقتان للنقل:

1. **بالسحب والإفلات (Drag & Drop)**: اسحب أي ملف أو مجلد (أو عدة عناصر محددة معاً) وأفلته مباشرة فوق مجلد آخر في نفس الصفحة، أو فوق أي اسم في شريط المسار (Breadcrumb) أعلى الصفحة — بما في ذلك "ملفاتي" للنقل إلى الجذر الرئيسي. يظهر إطار مميّز حول الهدف أثناء السحب لتأكيد مكان الإفلات.
2. **من القائمة**: اضغط زر النقاط الثلاث ← **"نقل"** ← ستظهر شجرة بكل مجلداتك ← اختر المجلد الوجهة (أو "الجذر الرئيسي") ← **"نقل هنا"**.

> ملاحظة: لا يمكن نقل مجلد إلى داخل نفسه أو إلى أحد مجلداته الفرعية، وسيمنعك النظام من ذلك مع رسالة توضيحية. سحب الملفات من خارج المتصفح (من جهازك) وإفلاتها في أي مكان بالصفحة يرفعها بدلاً من نقلها — راجع القسم 8.3.

### 8.8 التحديد المتعدد والإجراءات الجماعية

- اضغط على أي ملف/مجلد لتحديده (يظهر بخلفية ملوّنة).
- اضغط مع الاستمرار على `Ctrl` (أو `Cmd` على Mac) لتحديد أكثر من عنصر معاً.
- عند وجود عناصر محددة، يظهر شريط أدوات إضافي يتيح لك:
  - **تنزيل كملف مضغوط (ZIP)**: يجمع كل الملفات والمجلدات المحددة (بمحتوياتها الفرعية) في أرشيف واحد.
  - **حذف**: ينقل كل العناصر المحددة إلى سلة المحذوفات دفعة واحدة.

### 8.9 حذف ملف أو مجلد

اضغط زر النقاط الثلاث ← **"حذف"** ← تأكيد. لن يُحذف العنصر نهائياً، بل يُنقل إلى **سلة المحذوفات** (راجع القسم 10).

### 8.10 مؤشر المساحة التخزينية

أسفل القائمة الجانبية يظهر دائماً شريط يوضح **المساحة المستخدمة مقابل الحصة المسموح بها** لحسابك. عند الاقتراب من الحد الأقصى يتحول الشريط إلى اللون الأحمر. إن امتلأت المساحة بالكامل، سيرفض النظام أي عملية رفع جديدة مع رسالة توضيحية، وعليك حينها حذف بعض الملفات أو التواصل مع الإدارة لزيادة حصتك.

### 8.11 معلومات المجلد (بيانات بحثية/بيبلوغرافية)

عند الدخول إلى أي مجلد (وليس عند مستوى "ملفاتي" الرئيسي)، يظهر أعلى قائمة الملفات قسم قابل للطي بعنوان **"معلومات المجلد"**. اضغط عليه لإظهار/إخفاء **نوع المجلد** وحقوله المرتبطة به:

- اختر **"ملفات"** لمجلد عادي (لا حقول إضافية).
- اختر **"أطروحة"** لتمييز مجلد يضم رسالة علمية أو بحثاً أو كتاباً ممسوحاً ضوئياً — عند اختياره تظهر حقول قابلة للتعديل:
  - **اسم الباحث**
  - **المشرف**
  - **عنوان الرسالة**
  - **دار النشر**
  - **المكتبة الرقمية**
  - **سنة النشر**

عدّل ما تشاء ثم اضغط **"حفظ"**. كل الحقول اختيارية ومستقلة عن اسم المجلد نفسه — تركها فارغة لا يمنع استخدام المجلد بشكل طبيعي، وهي خاصة بكل مجلد على حدة ولا تنتقل تلقائياً إلى المجلدات الفرعية داخله. المجلدات المصنَّفة "أطروحة" تحمل شارة أرجوانية بعنوان **"أطروحة"** أسفل اسمها في شبكة الملفات، لتمييزها بصرياً عن باقي المجلدات دون الحاجة لفتحها.

## 9. دليل المشاركة والروابط العامة

### 9.1 إنشاء رابط مشاركة

1. اضغط زر النقاط الثلاث بجانب أي ملف أو مجلد ← **"مشاركة"**.
2. (اختياري) أدخل **كلمة مرور** للرابط — أي شخص يحصل على الرابط سيحتاج لإدخالها قبل رؤية الملف.
3. (اختياري) حدد **تاريخ/وقت انتهاء صلاحية** الرابط — بعده يصبح الرابط غير صالح تلقائياً.
4. (اختياري) حدد **حداً أقصى لعدد مرات التنزيل** — بعد بلوغه يتوقف الرابط عن العمل.
5. تحكم بخيار **"السماح بالتنزيل"** — عند تعطيله، تظهر معلومات الملف لكن دون زر تنزيل فعلي (مفيد لعرض الاسم/الحجم فقط).
6. اضغط **"إنشاء رابط المشاركة"**.

### 9.2 نسخ الرابط أو إرساله بالبريد

بعد إنشاء الرابط:

- ستظهر خانة تحتوي الرابط الكامل مع زر **نسخ** سريع.
- يمكنك مباشرة إدخال عنوان بريد إلكتروني واحد أو أكثر (مفصولة بفواصل) ورسالة اختيارية، ثم الضغط **"إرسال"** ليصل الرابط للمستلمين مباشرة عبر البريد الإلكتروني (يتطلب ضبط إعدادات SMTP في `.env` — راجع القسم 2).

### 9.3 إدارة الروابط النشطة

من القائمة الجانبية ← **"الروابط المشتركة"**، ستجد قائمة بكل الروابط التي أنشأتها، مع:

- اسم الملف/المجلد المرتبط بها.
- هل هي محمية بكلمة مرور.
- تاريخ الانتهاء (إن وُجد).
- عدد مرات التنزيل الحالي / الحد الأقصى (إن وُجد).
- زر **نسخ الرابط** مجدداً في أي وقت.
- زر **إلغاء المشاركة** لإبطال الرابط نهائياً بشكل فوري.

### 9.4 ماذا يرى الشخص الذي يفتح الرابط؟

- إن كان الرابط محمياً بكلمة مرور: تظهر له صفحة تطلب إدخالها أولاً.
- إن انتهت صلاحية الرابط أو بلغ الحد الأقصى للتنزيلات: تظهر رسالة توضح ذلك.
- في الحالة الطبيعية: تظهر له صفحة بسيطة تعرض اسم الملف/المجلد وحجمه (للملفات) مع زر تنزيل واحد — دون الحاجة لإنشاء حساب أو تسجيل دخول إطلاقاً.
- عند مشاركة **مجلد كامل**، يُبنى أرشيف ZIP لحظياً يحتوي كل محتوياته (بما فيها المجلدات الفرعية) عند الضغط على تنزيل.

## 10. دليل سلة المحذوفات

- من القائمة الجانبية ← **"سلة المحذوفات"**.
- تعرض الصفحة كل الملفات والمجلدات التي حذفتها ولم تُحذف نهائياً بعد.
- بجانب كل عنصر زرّان:
  - **استعادة** (↩): يعيد العنصر إلى مكانه الأصلي فوراً.
  - **حذف نهائي** (🗑): يحذف الملف من القرص ومن قاعدة البيانات بشكل **لا رجعة فيه**، ويُطلب تأكيد قبل التنفيذ.
- زر **"إفراغ سلة المحذوفات"** أعلى الصفحة يحذف كل شيء نهائياً دفعة واحدة (يتطلب تأكيداً أيضاً).
- **تنظيف تلقائي:** أي عنصر يبقى في السلة أكثر من المدة المحددة في الإعدادات (30 يوماً افتراضياً، القيمة `FILENEST_TRASH_RETENTION_DAYS`) يُحذف نهائياً تلقائياً عبر [المهمة المجدولة](#13-المهام-المجدولة-scheduler--cron) دون تدخل يدوي.

## 11. دليل واجهة الإدارة (Admin Panel)

الوصول إليها متاح فقط للمستخدمين الذين صلاحيتهم "مشرف"، عبر الرابط `/admin` أو زر **"لوحة الإدارة"** الذي يظهر في القائمة الجانبية للمشرفين فقط.

### 11.1 لوحة التحكم الرئيسية (`/admin`)

تعرض نظرة عامة سريعة:

- عدد المستخدمين الكلي وعدد الحسابات المفعّلة.
- عدد الملفات، عدد المجلدات، عدد روابط المشاركة النشطة.
- إجمالي المساحة التخزينية المستخدمة عبر كل الحسابات.
- قائمة **أعلى 5 مستخدمين** استهلاكاً للمساحة.
- قائمة **أحدث 15 نشاطاً** حصل في النظام (رفع ملف، إنشاء مشاركة، حذف مستخدم...).

### 11.2 إدارة المستخدمين (`/admin/users`)

**عرض المستخدمين:** جدول بكل المستخدمين مع: الاسم، البريد، الصلاحية، المساحة المستخدمة/الحصة، الحالة (مفعّل/معلّق). مربع بحث أعلى الجدول للبحث بالاسم أو البريد.

**إضافة مستخدم جديد:**
1. اضغط **"مستخدم جديد"**.
2. أدخل الاسم، البريد الإلكتروني، كلمة المرور.
3. اختر الصلاحية: **مستخدم** أو **مشرف**.
4. (اختياري) أدخل حصة تخزينية مخصصة بالميغابايت — اتركها فارغة لاستخدام الحصة الافتراضية العامة.
5. احفظ.

**تعديل مستخدم:**
1. اضغط أيقونة القلم (✏) بجانب المستخدم.
2. عدّل أي حقل (الاسم، البريد، الصلاحية، الحصة).
3. لتعليق الحساب مؤقتاً (منع تسجيل الدخول دون حذف بياناته): أزل التحديد من مربع **"الحساب مفعّل"**.
4. (اختياري) أدخل كلمة مرور جديدة لإعادة تعيينها للمستخدم.
5. احفظ.

**حذف مستخدم:**
اضغط أيقونة سلة المحذوفات (🗑) — **تحذير:** هذا الإجراء يحذف المستخدم **وجميع ملفاته ومجلداته على القرص نهائياً وفوراً بدون إمكانية استرجاع**، ولا يمكن للمشرف حذف حسابه الخاص من هذه الشاشة.

### 11.3 الإعدادات العامة (`/admin/settings`)

تنقسم صفحة الإعدادات إلى أربعة أقسام:

**أ) الهوية والعلامة التجارية**
- **اسم الموقع**: يظهر في عنوان المتصفح وشاشة تسجيل الدخول والقائمة الجانبية.
- **الشعار (Logo)**: صورة تظهر بجانب اسم الموقع في كل الصفحات.
- **صورة الترويسة**: صورة اختيارية إضافية (مخصصة لاستخدامات مستقبلية كصفحة هبوط أو رأس البريد الإلكتروني).

**ب) المظهر (السكن / Skin)**
- اختر أحد **12 لوناً جاهزاً** (Indigo, Slate, Emerald, Rose, Amber, Sky, Violet, Teal, Orange, Zinc, Cyan, Fuchsia) ليصبح هو اللون الأساسي لكل أزرار وروابط الواجهة في الموقع بالكامل فوراً بعد الحفظ.
- حقل **CSS مخصص**: لإضافة أي تنسيقات إضافية خاصة بك تُطبَّق فوق تصميم الموقع (متقدم، يتطلب معرفة بـ CSS).

**ج) التخزين والرفع**
- **الحصة الافتراضية للمستخدم الجديد** (ميغابايت): تُطبَّق تلقائياً عند تسجيل أي مستخدم جديد لا تُحدَّد له حصة يدوياً.
- **الحد الأقصى لحجم الملف الواحد** (ميغابايت): يُرفض أي رفع يتجاوز هذا الحجم على مستوى النظام بالكامل بغض النظر عن حصة المستخدم.

**د) اللغة والتسجيل**
- **اللغة الافتراضية**: العربية أو الإنجليزية — تُطبَّق على أي زائر جديد لم يحدد تفضيلاً شخصياً بعد (يمكن لكل مستخدم لاحقاً تغيير لغته الشخصية من صفحة "الملف الشخصي").
- **السماح بإنشاء حسابات جديدة ذاتياً**: عند تعطيله، يختفي رابط "إنشاء حساب جديد" ولا يمكن لأي زائر التسجيل بنفسه؛ يصبح إنشاء الحسابات محصوراً بالمشرف فقط عبر شاشة إدارة المستخدمين.

### 11.4 سجل النشاطات (`/admin/activity`)

سجل قابل للتصفح والترقيم (Pagination) لكل الأحداث المهمة في النظام: من قام برفع/حذف/مشاركة ماذا ومتى، بالإضافة إلى عنوان IP الخاص بالطلب. مفيد للمراجعة الأمنية أو تتبع نشاط مستخدم معيّن.

يحتوي أيضاً على:
- `forbidden_extensions`: قائمة امتدادات ممنوعة رفعها نهائياً لأسباب أمنية (php, exe, sh...) — لا يمكن تجاوزها حتى من لوحة الإدارة، وتعديلها يتطلب الوصول لكود المشروع مباشرة.
- `skins`: قائمة أسماء السكنات المتاحة في لوحة الإدارة.
- `supported_locales`: اللغات المدعومة واتجاه كل منها (rtl/ltr).

### ج) إعدادات لوحة الإدارة (لا تتطلب وصولاً للسيرفر)

كل ما ورد في القسم [11.3](#113-الإعدادات-العامة-adminsettings) يُحفظ مباشرة في جدول `settings` بقاعدة البيانات ويُطبَّق فوراً على كامل الموقع دون الحاجة لإعادة تشغيل أي شيء.

### د) تفضيلات المستخدم الشخصية

من **الملف الشخصي والإعدادات** (أعلى يمين الصفحة ← اسم المستخدم ← "الملف الشخصي والإعدادات")، يمكن لكل مستخدم بشكل مستقل:

- اختيار لغة واجهته الشخصية (تتجاوز اللغة الافتراضية العامة للموقع بالنسبة له فقط).
- تغيير كلمة المرور.
- حذف حسابه نهائياً (يتطلب إدخال كلمة المرور للتأكيد).

## 13. المهام المجدولة (Scheduler / Cron)

يحتوي النظام على أمرين مجدولين معرَّفين في `routes/console.php`:

```php
Schedule::command('filenest:purge-trash')->daily();          // حذف نهائي لعناصر السلة المنتهية المدة
Schedule::command('filenest:purge-stale-uploads')->hourly();  // تنظيف جلسات رفع متروكة/فاشلة وأجزائها المؤقتة
```

لتفعيل الجدولة فعلياً على السيرفر، أضف سطر Cron واحد فقط (لا حاجة لأي سطر آخر مهما زاد عدد الأوامر المجدولة مستقبلاً):

```bash
crontab -e
```

أضف السطر التالي:

```
* * * * * cd /path/to/filemanager && php artisan schedule:run >> /dev/null 2>&1
```

يمكنك اختبار الأوامر يدوياً في أي وقت للتأكد من عملها:

```bash
php artisan filenest:purge-trash
php artisan filenest:purge-stale-uploads
```

## 14. بنية قاعدة البيانات

| الجدول | الوصف |
|---|---|
| `users` | المستخدمون، إضافة إلى الحقول الافتراضية: `role` (admin/user)، `is_active`، `storage_quota_bytes`، `storage_used_bytes`، `locale`، `theme` |
| `folders` | المجلدات، شجرة ذاتية الإشارة عبر `parent_id`، مع Soft Delete (`deleted_at`) لدعم سلة المحذوفات |
| `files` | الملفات، مرتبطة بمالكها (`user_id`) ومجلدها (`folder_id`)، تخزّن المسار الفعلي على القرص، النوع، الحجم |
| `shares` | روابط المشاركة، علاقة متعددة الأشكال (Polymorphic) مع `files` أو `folders`، مع `token`, `password`, `expires_at`, `max_downloads`, `download_count` |
| `share_emails` | سجل كل بريد إلكتروني أُرسل إليه رابط مشاركة، مع الرسالة المرفقة ووقت الإرسال |
| `settings` | مخزن مفتاح/قيمة لكل إعدادات لوحة الإدارة العامة، مع تخزين مؤقت (Cache) تلقائي |
| `activity_logs` | سجل كل الأحداث المهمة في النظام |
| `file_upload_sessions` | تتبع جلسات الرفع المُجزّأ الجارية (الأجزاء المستلمة حتى الآن، الحجم الكلي...) |

> ملاحظة تصميم مهمة: الملفات تُخزَّن فعلياً على القرص بأسماء عشوائية فريدة (UUID) داخل مجلد كل مستخدم (`storage/app/filemanager/{user_id}/...`)، بينما الشجرة المنطقية للمجلدات (الأسماء، الترتيب، النقل، إعادة التسمية) تُدار بالكامل داخل قاعدة البيانات فقط. هذا يجعل عمليات النقل وإعادة التسمية فورية (تحديث سجل واحد في قاعدة البيانات) دون الحاجة لنقل أو إعادة تسمية ملفات فعلية على القرص، وهو نفس الأسلوب المتبع في خدمات التخزين السحابي الحديثة.

## 16. الأمان

- **عزل بيانات المستخدمين**: كل الاستعلامات مقيّدة بـ `user_id` صاحب الجلسة، ومحمية إضافياً عبر Policies (`FilePolicy`, `FolderPolicy`, `SharePolicy`) — أي محاولة وصول لملف/مجلد/مشاركة لا يملكها المستخدم تُرفض بخطأ 403، حتى لو خمّن رقم المعرّف (ID) بشكل مباشر في الرابط.
- **امتدادات ممنوعة دائماً**: لا يمكن رفع ملفات تنفيذية خطرة (`php`, `phtml`, `exe`, `sh`, `bat`...) بغض النظر عن أي إعداد آخر.
- **روابط المشاركة**: التوكن عشوائي طويل (40 حرفاً) غير قابل للتخمين، مع دعم كلمة مرور مُشفّرة (`bcrypt`)، وتنتهي صلاحيتها تلقائياً حسب التاريخ أو عدد التنزيلات.
- **الحسابات المعلَّقة**: أي حساب يُعطَّل من لوحة الإدارة يُسجَّل خروجه فوراً من كل الجلسات المفتوحة عند أول طلب تالٍ.
- **CSRF & XSS**: محمي بشكل افتراضي عبر آليات Laravel القياسية (توكن CSRF، تنقية الإخراج في Vue/Blade).
- **التسجيل الذاتي**: يمكن تعطيله بالكامل من لوحة الإدارة لتحويل النظام إلى نظام "دعوة فقط" (Invite-only) تُدار حساباته من قِبل المشرف حصراً — ويُطبَّق هذا القيد على التسجيل عبر الـAPI أيضاً وليس الويب فقط.
- **لا ترقية إلى مشرف إلا من المدير الرئيسي**: إنشاء حساب مشرف جديد أو ترقية مستخدم موجود إلى دور "مشرف" يتطلب صلاحية المدير الرئيسي حصراً، حتى لو كان المستخدم الحالي مشرفاً فرعياً يملك صلاحية "إدارة المستخدمين" — لأن دور المشرف نفسه يتجاوز كل فحوصات ملكية الملفات (`FilePolicy`/`FolderPolicy`) بغض النظر عن أي صلاحية فرعية أخرى، فمنح هذا الدور بلا قيد كان يعني إمكانية صنع مشرف فرعي لحساب نظير يملك وصولاً كاملاً لملفات كل المستخدمين.
- **تغيير كلمة المرور يُبطل الرموز الأخرى**: عند تغيير كلمة المرور (من الويب أو عبر الـAPI)، تُبطَل كل رموز الوصول (Personal Access Tokens) الأخرى المرتبطة بالحساب تلقائياً (باستثناء الرمز المستخدم لتنفيذ الطلب نفسه عبر الـAPI) — بحيث لا يبقى أي رمز مسروق أو جهاز غير موثوق متصلاً بعد أن يتفاعل المستخدم مع اختراق محتمل بتغيير كلمة المرور.
- **إعدادات المصادقة الثنائية محمية بكلمة المرور**: تفعيل/تأكيد/تعطيل المصادقة الثنائية أو توليد رموز استرداد جديدة يتطلب دائماً تأكيد كلمة المرور الحالية (عبر صفحة "تأكيد كلمة المرور" في الويب، أو حقل `password` في الـAPI) — بحيث لا تكفي جلسة أو رمز وصول مسروق وحده للاستيلاء الصامت على إعداد المصادقة الثنائية لحساب الضحية أو تعطيله.

## 18. استكشاف الأخطاء الشائعة

| المشكلة | الحل |
|---|---|
| صفحة بيضاء أو خطأ 500 بعد الرفع على السيرفر | تأكد من صلاحيات الكتابة على `storage/` و`bootstrap/cache/` (راجع الخطوة 10 في التثبيت) |
| الشعار لا يظهر بعد رفعه من لوحة الإعدادات | تأكد من تنفيذ `php artisan storage:link` |
| فشل الرفع دائماً عند نسبة معينة على السيرفر (وليس محلياً) | راجع `client_max_body_size` في Nginx أو `LimitRequestBody`/`upload_max_filesize` و`post_max_size` في PHP — يجب أن تكون أكبر من حجم الجزء الواحد `FILENEST_CHUNK_SIZE_MB` |
| رسالة "The chunk failed to upload" أثناء الرفع (خصوصاً لملفات كبيرة كالفيديو) | هذه رسالة Laravel القياسية عند رفض PHP نفسه لجزء الملف (`UPLOAD_ERR_INI_SIZE` وما شابه) — أي أن `upload_max_filesize` أو `post_max_size` في `php.ini` أصغر من حجم الجزء `FILENEST_CHUNK_SIZE_MB` (الافتراضي 2 ميغابايت). ارفع القيمتين في `php.ini` لتكونا أكبر من حجم الجزء ثم أعد تشغيل الخادم، **أو** بدلاً من ذلك اخفض `FILENEST_CHUNK_SIZE_MB` في `.env` إلى ما دون حدّي PHP الحاليين ثم شغّل `php artisan config:clear` |
| لا تصل رسائل مشاركة الملفات بالبريد | تحقق من إعدادات `MAIL_*` في `.env`، وشغّل `php artisan queue:work` إن كانت `QUEUE_CONNECTION` غير `sync` |
| التعديلات في `.env` لا تظهر أثرها | إن كنت قد شغّلت `php artisan config:cache` سابقاً، أعد تشغيله بعد كل تعديل: `php artisan config:cache` |
| عناصر سلة المحذوفات لا تُحذف نهائياً تلقائياً | تأكد من إضافة سطر Cron الخاص بـ `schedule:run` (راجع القسم 13) |
| رسالة "لا توجد مساحة تخزين كافية" رغم توفر مساحة ظاهرياً | تحقق من قيمة `storage_quota_bytes`/`storage_used_bytes` للمستخدم من لوحة الإدارة، فقد تكون الحصة المخصصة له أقل من الافتراضية |

- **فحص الملفات المرفوعة بمضاد فيروسات (ClamAV)** — مهم خصوصاً مع تفعيل الرفع العام أو الرفع من رابط خارجي.
- **نسخ سابقة للملف (Version History)** — الاحتفاظ بالنسخ القديمة عند إعادة رفع/استبدال ملف، مع إمكانية الاسترجاع.
- **OCR على الصور والملفات الممسوحة ضوئياً** — امتداد طبيعي لميزة فهرسة المحتوى (القسم 21)، يجعل حتى المستندات الممسوحة ضوئياً قابلة للبحث.

### تنظيم واستخدام يومي
- **مفضّلة / الأخيرة / لوحة وصول سريع** (Starred, Recent) كما في Drive وDropbox.
- **وسوم/تصنيفات (Tags)** على الملفات عابرة للمجلدات.
- **مشاركة مجلد مع مستخدم آخر داخل النظام** (وليس رابط عام فقط) مع صلاحيات قراءة/كتابة، مشابه لـ Google Shared Drives.
- **كشف الملفات المكررة** عبر بصمة المحتوى (checksum) عند الرفع.

### تكامل وتوسّع
- **WebDAV** لتركيب المساحة كقرص شبكي (كما في Nextcloud/ownCloud).
- **مفاتيح API شخصية (Personal Access Tokens من الواجهة)** لإصدار/إلغاء عدة رموز دخول للتكاملات الخارجية (Zapier-style) من صفحة الحساب مباشرة، فوق ما توفره واجهة API الحالية (القسم 23).
- **إشعارات داخل الواجهة (Notification Center)** بجانب البريد الإلكتروني الحالي.
- تكامل مع تخزين سحابي خارجي (S3) كخيار بديل لتخزين الملفات — البنية الحالية (`config/filesystems.php`) تدعم ذلك جاهزاً بإضافة قرص `s3` وتفعيله في `filenest.disk`.

### متقدّمة/اختيارية
- تشفير من طرف إلى طرف (End-to-End) كما في Proton Drive/Tresorit.
- معاينة مستندات Office داخل المتصفح مباشرة (عبر OnlyOffice/Collabora).
- استيراد من Google Drive/Dropbox عبر OAuth عند التسجيل.
- نسخة PWA (تثبيت من المتصفح) بجانب تطبيق Flutter الأصلي الحالي (القسم 24).
- ترجمة كاملة لأكثر من لغتين (البنية تدعم إضافة أي عدد من اللغات عبر `lang/<code>.json`، لكن المُرفَق حالياً هو العربية والإنجليزية فقط).

## 20. الميزات المتقدمة: الصلاحيات، OAuth، الضيوف، الأمان، والمزيد

هذا القسم يوثّق مجموعة الميزات التي أُضيفت في الإصدار الثاني من المشروع، والتي تقارب FileNest أكثر من ميزات الأنظمة التجارية المشابهة.

### 20.1 الأدوار ومصفوفة الصلاحيات (`/admin/permissions`)

بالإضافة إلى دوري **مستخدم** و**مشرف**، يدعم النظام الآن:

| الدور | الوصف |
|---|---|
| `admin` | صلاحيات كاملة دائماً، لا يظهر في مصفوفة الصلاحيات. |
| `editor` (محرّر) | يمكنه الرفع/التسمية/النقل، لكن لا يمكنه الحذف أو النسخ افتراضياً. |
| `contributor` (مساهم) | يمكنه الرفع وإنشاء مجلدات فقط، بقية الإجراءات معطّلة افتراضياً. |
| `guest` (زائر) | لا حساب له إطلاقاً؛ يُستخدم فقط عند تفعيل "الوصول كضيف"، ومحصور بالعرض/التحميل/المشاركة. |

من صفحة **الصلاحيات** في لوحة الإدارة، يمكن للمشرف الرئيسي تفعيل/تعطيل أي إجراء (عرض، تحميل، مشاركة، رفع، حذف، تسمية، نقل، نسخ، إنشاء مجلد، حذف مجلد، تسمية مجلد) لكل دور بشكل مستقل، والتغيير يُطبَّق فوراً على كل طلب لاحق دون الحاجة لإعادة تسجيل الدخول.

### 20.2 تسجيل الدخول عبر Google / GitHub / LinkedIn

من صفحة **الأمان وتسجيل الدخول** (`/admin/security`)، أدخل Client ID وClient Secret لكل مزوّد تريد تفعيله. رابط إعادة التوجيه (Redirect URI) الذي يجب تسجيله في لوحة تحكم كل مزوّد هو:

```
https://your-domain.com/auth/google/redirect
https://your-domain.com/auth/github/redirect
https://your-domain.com/auth/linkedin/redirect
```

- **Google**: أنشئ بيانات اعتماد OAuth من [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
- **GitHub**: من إعدادات حسابك → Developer settings → OAuth Apps.
- **LinkedIn**: من [LinkedIn Developer Portal](https://www.linkedin.com/developers/apps) (يستخدم النظام بروتوكول LinkedIn الأحدث المبني على OpenID Connect).

عند أول تسجيل دخول عبر أحد هذه المزوّدين، يُنشأ حساب جديد تلقائياً (بنفس الدور الافتراضي المحدد في "الإعدادات العامة")، أو يُربط بحساب موجود مسبقاً بنفس البريد الإلكتروني. تسجيل الدخول عبر هذه المزوّدات يخضع أيضاً لإعداد "السماح بإنشاء حسابات جديدة ذاتياً" — إن كان معطّلاً، لا يمكن لمستخدم جديد الدخول عبر OAuth أيضاً.

### 20.3 التصفح كضيف (بدون تسجيل دخول)

1. من **الأمان** فعّل "السماح للزوار غير المسجّلين بتصفح المجلدات العامة".
2. من صفحة الملفات، افتح قائمة أي مجلد جذري واختر "جعله مجلداً عاماً" (يظهر هذا الخيار للمشرف فقط). كل ما تحت هذا المجلد يصبح متاحاً للزوار تلقائياً.
3. يمكن الوصول للتصفح العام من الرابط `/public` بدون أي تسجيل دخول.
4. صلاحيات الزائر (عرض/تحميل) تُضبط من نفس مصفوفة الصلاحيات في القسم 20.1، صف "زائر".

### 20.4 رمز التحقق (Captcha) وGoogle reCAPTCHA

من **الأمان**، يمكن تفعيل رمز تحقق على: صفحة التسجيل، صفحة استعادة كلمة المرور، وتنزيل الزوار من رابط مشاركة عام. افتراضياً يُستخدم سؤال رياضي بسيط ("3 + 5 = ؟") لا يتطلب أي إعداد إضافي. لاستخدام Google reCAPTCHA بدلاً منه، فعّل الخيار وأدخل Site Key وSecret Key من [Google reCAPTCHA Admin](https://www.google.com/recaptcha/admin) (يدعم كلا النمطين العادي والغير مرئي Invisible).

### 20.5 حظر/سماح عناوين IP

من **الأمان**، اختر النمط:

- **معطّل**: لا قيود.
- **قائمة حظر (Blacklist)**: كل عنوان مُدرَج يُمنع من الوصول للموقع بالكامل، والباقي مسموح.
- **قائمة سماح (Whitelist)**: فقط العناوين المُدرَجة يُسمح لها بالوصول، وما عداها يُمنع.

يمكن إدخال عنوان مفرد (`203.0.113.5`) أو نطاق CIDR (`10.0.0.0/8`)، مع رابط إعادة توجيه اختياري بدل رسالة الحظر الافتراضية.

### 20.6 الرفع من رابط خارجي (Remote Upload)

بعد تفعيله من **الأمان**، يظهر زر "رفع من رابط" في شريط أدوات الملفات. يتحقق النظام من أن الرابط لا يشير إلى عنوان IP داخلي/خاص (مثل `127.0.0.1` أو `169.254.169.254` أو نطاقات `10.x`/`172.16-31.x`/`192.168.x`) لمنع هجمات SSRF، ولا يتبع أي إعادة توجيه (redirect) تلقائياً، ويُطبَّق عليه نفس حدود حجم الملف وقائمة الامتدادات المعتمدة على الرفع العادي.

### 20.7 روابط المشاركة المختصرة والاستخدام لمرة واحدة

- من **الإعدادات العامة**، فعّل "استخدام روابط مشاركة مختصرة" ليُعرض رابط بصيغة `/s/x/AbCdEfG` بدل الرابط الطويل بالكامل عند إنشاء أي مشاركة جديدة.
- عند إنشاء مشاركة، فعّل خيار "رابط للاستخدام مرة واحدة فقط" ليُلغى الرابط تلقائياً فور أول عملية تنزيل ناجحة، حتى لو لم يصل لحد التنزيلات المحدد يدوياً.

### 20.8 إعدادات البريد الإلكتروني (SMTP) من لوحة الإدارة

صفحة **البريد الإلكتروني** (`/admin/mail`) تتيح إدخال بيانات خادم SMTP (المضيف، المنفذ، اسم المستخدم، كلمة المرور، نوع التشفير، عنوان واسم المرسل) مباشرة من الواجهة، دون الحاجة للوصول للسيرفر وتعديل `.env`. هناك أيضاً زر لإرسال رسالة اختبار للتأكد من صحة الإعدادات فوراً.

من نفس الصفحة، يمكن تفعيل إشعارات بريدية تلقائية تُرسل لكل مشرف نشط عند: رفع ملف، تحميل ملف، تسجيل دخول مستخدم، إنشاء مجلد جديد، أو انضمام مستخدم جديد.

### 20.9 قائمة امتدادات الملفات المسموحة/الممنوعة

من **الإعدادات العامة**، اختر نمط "حظر الامتدادات التالية فقط" أو "السماح بالامتدادات التالية فقط"، ثم أدخل قائمة الامتدادات مفصولة بفواصل (مثال: `exe, bat, sh`). هذه القائمة إضافية فوق حماية أمنية ثابتة غير قابلة للتعطيل (`php, phtml, php3, php4, php5, phar, exe, sh, bat, cmd` في `config/filenest.php`) تمنع رفع ملفات قابلة للتنفيذ على الخادم بغض النظر عن أي إعداد.

### 20.10 لوحة التحليلات (`/admin/analytics`)

رسم بياني تفاعلي (Chart.js) يعرض عدد عمليات الرفع والتحميل والمشاركة يومياً على مدى 7/30/90 يوماً، مع بطاقات إجمالية لكل نوع حدث. تعتمد البيانات على سجل النشاطات (`activity_logs`) المسجَّل تلقائياً مع كل عملية.

### 20.11 عدة مشرفين بصلاحيات محدودة (Sub-admins)

أول حساب مشرف يُنشئه معدّ التثبيت (seeder) هو **المدير الرئيسي** (Master Admin) وله دائماً كل الصلاحيات ولا يمكن حذفه أو تعديل دوره من قِبل أي شخص آخر. عند إنشاء مشرف آخر، يمكن للمدير الرئيسي فقط تحديد أي من الصلاحيات الإدارية التالية يملكها:

- إدارة المظهر (الشعار، الألوان، الترويسة).
- إدارة المستخدمين.
- إدارة الترجمات.
- عرض التحليلات وسجل النشاطات.
- إدارة الإعدادات العامة (بما فيها الصلاحيات، الأمان، البريد).

أي صفحة إدارية يفتحها مشرف لا يملك صلاحيتها المطلوبة تُرجع خطأ 403، وتختفي روابطها من القائمة الجانبية تلقائياً.

### 20.12 محرّر الترجمات (`/admin/translations`)

النظام يحمّل نصوص الواجهة من ملفات `lang/ar.json` و`lang/en.json` كنصوص أساسية، ويسمح لأي مشرف يملك صلاحية "إدارة الترجمات" بتعديل أي نص لأي لغة من صفحة **الترجمات** دون الحاجة لتعديل أي ملف على الخادم — التعديلات تُخزَّن في قاعدة البيانات (`translation_overrides`) وتتجاوز النص الأصلي، مع زر "الأصلي" لإعادة أي نص لقيمته الافتراضية. لإضافة لغة جديدة بالكامل، أضف مفتاحها إلى `config/filenest.supported_locales` وأنشئ ملف `lang/<code>.json` بنفس بنية الملفين الحاليين.

### 20.13 بث الفيديو والصوت مع دعم التقديم (Seek)

معاينة ملفات الفيديو والصوت من داخل المتصفح تدعم الآن طلبات HTTP Range، مما يسمح بالتقديم السريع لأي نقطة في الملف دون الحاجة لتحميله بالكامل أولاً — مفيد بشكل خاص لملفات الفيديو الكبيرة.

## 21. فهرسة محتوى المستندات (بحث شبيه بالمكتبات)

عند رفع أي مستند (وليس فقط اسمه)، يستخرج النظام تلقائياً النص الموجود **داخل** الملف ويربطه به في قاعدة البيانات، بحيث يصبح البحث قادراً على إيجاد الملف من محتواه — تماماً كما تفعل فهارس المكتبات ودور النشر مع الكتب والمستندات.

### 21.1 الصيغ المدعومة

| الصيغة | الطريقة |
|---|---|
| PDF | مكتبة `smalot/pdfparser` |
| Word (`.docx`) | مكتبة `phpoffice/phpword` |
| Word القديم (`.doc`) | نفس المكتبة، بأفضل جهد ممكن (بعض ملفات `.doc` القديمة جداً أو المعقدة قد لا تُقرأ) |
| PowerPoint (`.pptx`) | مُحلِّل مخصّص خفيف مبني داخل المشروع (انظر الملاحظة الأمنية أدناه) |
| نصوص (`.txt`, `.md`, `.csv`, `.json`, `.log`) | قراءة مباشرة |

> **ملاحظة أمنية حول PowerPoint:** لم تُستخدم مكتبة `phpoffice/phppresentation` الشائعة لقراءة ملفات `.pptx`، لأنها تفرض الاعتماد على نسخ من `phpoffice/phpspreadsheet` تحتوي على عدة ثغرات أمنية معروفة (منها ثغرة تنفيذ كود عن بُعد حرجة CVE-2026-34084) دون وجود نسخة مُصلَحة متوافقة معها. بدلاً من ذلك، يحتوي المشروع على مُحلِّل بسيط مبني يدوياً (في `app/Services/DocumentTextExtractor.php`) يفتح ملف PowerPoint كأرشيف ZIP عادي (وهذا كل ما هو عليه فعلياً) ويستخرج النص من ملفات الشرائح XML مباشرة، دون أي اعتماديات إضافية أو مخاطر أمنية.
>
> ملفات PowerPoint القديمة (`.ppt` بصيغة OLE الثنائية) غير مدعومة حالياً لعدم وجود مكتبة PHP نقية وآمنة لقراءتها.

### 21.2 كيف يعمل

1. عند اكتمال الرفع (سواء رفعاً عادياً أو من رابط خارجي)، تُرسَل مهمة استخراج نص (`App\Jobs\ExtractFileText`) إلى نظام الطوابير — تعمل فوراً إن كان `QUEUE_CONNECTION=sync`، أو في الخلفية عبر عامل طابور (`php artisan queue:work`) إن كان الإعداد `database` أو غيره (راجع القسم 13).
2. يُستخرَج النص، يُنظَّف من التكرارات والمسافات الزائدة، ويُحفَظ في عمود `content_text` الخاص بالملف (محدود بحد أقصى ~2 مليون حرف لكل ملف).
3. عند البحث، يُطابَق النص المُدخَل مع **اسم الملف وأيضاً محتواه** معاً. على MySQL يُستخدم فهرس نصي كامل (`FULLTEXT`) لأداء أفضل؛ على أي قاعدة بيانات أخرى (مثل SQLite في بيئة التطوير) يُستخدم بحث `LIKE` كبديل.
4. عند نسخ ملف (ميزة Copy)، يُنسَخ النص المُستخرَج مسبقاً مباشرة دون إعادة تحليل الملف من جديد (المحتوى مطابق تماماً).
5. في نتائج البحث، يظهر مقطع قصير (Snippet) من داخل المستند حول موضع الكلمة المطابقة — مشابه لما تعرضه فهارس المكتبات ومحركات البحث.
6. أيقونة صغيرة (🔍 عدسة تكبير على مستند) تظهر بجانب اسم أي ملف تمت فهرسته بنجاح.

### 21.3 الإعدادات

من **الإعدادات العامة** (`/admin/settings`):

- **تفعيل استخراج النص وفهرسته تلقائياً**: تشغيل/إيقاف الميزة بالكامل (مفعّلة افتراضياً).
- **لا تُفهرس الملفات الأكبر من (ميغابايت)**: حد أقصى لحجم الملف قبل تخطي فهرسته (الافتراضي 25 ميغابايت)، لتفادي استهلاك موارد الخادم على ملفات ضخمة.

### 21.4 ملاحظات أداء وخصوصية

- الاستخراج فشل الصمت (Silent-fail): أي ملف تالف أو مشفّر أو غير مدعوم لا يوقف عملية الرفع أبداً — يُتجاهَل فقط استخراج نصه.
- نص المحتوى المُستخرَج **لا يُرسَل أبداً إلى المتصفح مباشرة** (محجوب من التسلسل الافتراضي للنموذج)؛ فقط مقتطف قصير (Snippet) يُرسَل عند وجود تطابق بحث فعلي.
- لأي منشأة تتعامل مع مستندات حسّاسة، يمكن تعطيل الفهرسة بالكامل من الإعدادات أعلاه في أي وقت.

## 22. الصور المصغّرة (Thumbnails)

بدلاً من الاكتفاء بأيقونة عامة لكل ملف، يولّد النظام صورة مصغّرة حقيقية تعكس محتوى الملف فعلياً — تماماً كما تفعل Google Drive وDropbox وNextcloud.

### 22.1 ما الذي يُولَّد ومتى

| النوع | الأداة المستخدمة | التوفّر |
|---|---|---|
| الصور (`jpg, png, gif, webp, bmp`) | امتداد PHP `GD` | متوفر دائماً تقريباً في أي تثبيت PHP |
| الفيديو (أول إطار عند الثانية 1، `mp4, mov, avi, mkv, webm, m4v`) | أداة `ffmpeg` على مستوى النظام | **اختياري** — يجب تثبيتها على الخادم |
| أول صفحة من PDF | امتداد PHP `Imagick` (مع محرّك Ghostscript) | **اختياري** — يجب تثبيت الامتداد على الخادم |

عند عدم توفر `ffmpeg` أو `Imagick`، لا يحدث أي خطأ — يُتجاهَل توليد الصورة المصغّرة لذلك الملف فقط وتظهر الأيقونة العامة بدلاً منها، بنفس فلسفة "فشل صامت" المستخدمة في فهرسة المحتوى (القسم 21).

### 22.2 كيف يعمل

1. عند اكتمال الرفع (عادياً أو من رابط خارجي)، تُرسَل مهمة توليد صورة مصغّرة (`App\Jobs\GenerateThumbnail`) إلى نظام الطوابير، بالتوازي مع مهمة استخراج النص.
2. تُنشأ الصورة المصغّرة بأبعاد قابلة للتحكم (الحد الأقصى الافتراضي 400×400 بكسل مع الحفاظ على أبعاد الصورة الأصلية)، وتُخزَّن كملف JPEG منفصل بجانب الملف الأصلي.
3. تُعرض الصورة المصغّرة في شبكة الملفات وفي صفحة التصفح العام للزوار، مع رجوع تلقائي للأيقونة العامة إذا تعذّر تحميلها.
4. عند نسخ ملف (ميزة Copy)، تُنسَخ الصورة المصغّرة الموجودة مباشرة دون إعادة توليدها.
5. عند حذف ملف نهائياً من سلة المحذوفات، تُحذف الصورة المصغّرة المرتبطة به تلقائياً.

### 22.3 الإعدادات

من **الإعدادات العامة** (`/admin/settings`):

- **تفعيل توليد الصور المصغّرة تلقائياً**: تشغيل/إيقاف الميزة بالكامل (مفعّلة افتراضياً).
- **أقصى أبعاد للصورة المصغّرة (بكسل)**: يتحكم بحجم أكبر بُعد في الصورة الناتجة (الافتراضي 400).

## 23. REST API (لتطبيق الجوّال Flutter وأي عميل خارجي)

بالإضافة إلى واجهة الويب (Inertia/Vue)، يوفّر FileNest واجهة برمجية (API) كاملة مبنية على [Laravel Sanctum](https://laravel.com/docs/sanctum) بنظام رموز الوصول الشخصية (Personal Access Tokens)، مصمَّمة خصيصاً لتطبيق الجوّال (Flutter) الموصوف في القسم التالي، لكنها صالحة لأي عميل خارجي (تطبيق سطح مكتب، سكربت، تكامل خارجي...).

### 23.1 مبادئ التصميم

- **بدون جلسات (Stateless)**: المصادقة عبر ترويسة `Authorization: Bearer <token>` فقط — لا اعتماد على الكوكيز أو CSRF، مناسب تماماً لتطبيق جوّال.
- **إصدار (Versioning)**: كل المسارات تحت البادئة `/api/v1/...` حتى يمكن إضافة `v2` لاحقاً دون كسر التوافق مع تطبيقات قديمة.
- **نفس منطق الصلاحيات**: كل نقطة نهاية تمر بنفس فحوصات `RolePermission`/Policies المستخدمة في واجهة الويب (لا صلاحيات إضافية أو مختلفة).
- **تحديد معدّل الطلبات (Rate Limiting)**: مسارات التسجيل/الدخول محدودة بـ 10 طلبات/دقيقة لكل IP، وبقية المسارات المصادَق عليها بـ 120 طلب/دقيقة لكل مستخدم.
- **استجابات JSON موحّدة**: كل خطأ (تحقق، صلاحيات، 404...) يعود كـ JSON قياسي بفضل `shouldRenderJsonWhen` في `bootstrap/app.php`.

### 23.2 المصادقة

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/v1/auth/register` | تسجيل حساب جديد (`name`, `email`, `password`, `password_confirmation`) — يُعيد المستخدم ورمز وصول جاهز للاستخدام فوراً |
| POST | `/api/v1/auth/login` | تسجيل الدخول (`email`, `password`, `device_name` اختياري) |
| POST | `/api/v1/auth/two-factor-challenge` | إكمال الدخول عند تفعيل 2FA (انظر أدناه) |
| POST | `/api/v1/auth/logout` | إبطال رمز الوصول الحالي فقط (يتطلب `Bearer`) |
| GET | `/api/v1/auth/me` | بيانات المستخدم الحالي (يتضمن `two_factor_enabled`) + حالة استخدام التخزين (يتطلب `Bearer`) |

كل رمز وصول مرتبط باسم جهاز (`device_name`) حتى يمكن للمستخدم لاحقاً رؤية/إلغاء أجهزته من إعدادات حسابه.

#### المصادقة الثنائية (2FA) عبر الـAPI

بما أن الـAPI بلا حالة (Stateless) ولا توجد جلسة خادم كما في الويب، يستجيب `/auth/login` بشكل مختلف عندما تكون المصادقة الثنائية مفعّلة على الحساب: بدلاً من رمز وصول فوري، يعود برمز مؤقت (صالح 5 دقائق، مشفَّر ذاتياً بدون تخزين على الخادم) يُستخدَم لإكمال الدخول:

```json
// استجابة /auth/login عند تفعيل 2FA
{ "two_factor_required": true, "two_factor_token": "eyJpdiI6Ii4uLg==" }

// استجابة /auth/login بدون 2FA (كما كانت)
{ "two_factor_required": false, "user": { ... }, "token": "1|..." }
```

بعدها يُستدعى `POST /api/v1/auth/two-factor-challenge` بـ`{two_factor_token, code}` (رمز التطبيق) أو `{two_factor_token, recovery_code}` (رمز استرداد) ليُعاد رمز الوصول الفعلي `{user, token}`.

نقاط نهاية إدارة المصادقة الثنائية نفسها (يتطلب `Bearer`)، تعادل تماماً واجهة الويب في القسم 25 — **الأربعة جميعها تتطلب حقل `password` بكلمة المرور الحالية الصحيحة** في كل استدعاء (مكافئ الـAPI الخالي من الجلسات لصفحة "تأكيد كلمة المرور" في الويب)، حتى لا يكفي رمز وصول مسروق وحده للاستيلاء الصامت على إعداد 2FA:

| الطريقة | المسار | الوصف |
|---|---|---|
| POST | `/api/v1/user/two-factor-authentication` | `{password}` — توليد مفتاح سري جديد (غير مفعّل بعد)، يُعيد `{secret, qr_code_uri}` |
| POST | `/api/v1/user/confirmed-two-factor-authentication` | `{password, code}` — تأكيد التفعيل، يُعيد `{recovery_codes}` (8 رموز، لمرة واحدة) |
| DELETE | `/api/v1/user/two-factor-authentication` | `{password}` — تعطيل |
| POST | `/api/v1/user/two-factor-recovery-codes` | `{password}` — توليد مجموعة رموز استرداد جديدة تستبدل القديمة |

### 23.4 رفع الملفات (رفع مجزّأ Chunked)

نفس آلية الرفع المستخدمة في واجهة الويب، بأربع خطوات JSON بسيطة تناسب تطبيق جوّال على شبكة غير مستقرة:

1. `POST /api/v1/uploads/init` — `{name, size, folder_id?}` يُعيد `identifier` و`chunk_size` وعدد الأجزاء. **قابل للاستئناف**: استدعاؤه مرة أخرى بنفس (الاسم، الحجم، المجلد) بينما جلسة سابقة لا تزال قيد الرفع يعيد نفس `identifier` مع `received_chunks` (الأجزاء المستلمة فعلاً) و`resumed: true`، بدلاً من إنشاء جلسة جديدة — هذا ما يتيح لتطبيق الجوّال إكمال رفع تعطّل بسبب انقطاع الشبكة أو إغلاق التطبيق دون البدء من الصفر.
2. `POST /api/v1/uploads/chunk` — `multipart/form-data`‏ (`identifier`, `index`, `chunk`) لكل جزء غير موجود في `received_chunks`؛ يمكن إعادة إرسال جزء فشل دون إعادة الرفع بالكامل.
3. `POST /api/v1/uploads/finalize` — `{identifier}` بعد اكتمال كل الأجزاء، يُعيد بيانات الملف النهائي (ويُشغّل تلقائياً استخراج النص وتوليد الصورة المصغّرة في الخلفية).
4. `POST /api/v1/uploads/cancel` — `{identifier}` لإلغاء رفع جارٍ وحذف الأجزاء المؤقتة نهائياً (بعدها لا يمكن استئنافه).

### 23.6 إدارة الحساب الشخصي واستعادة كلمة المرور

| الطريقة | المسار | الوصف |
|---|---|---|
| PUT | `/api/v1/profile` | تحديث الاسم/البريد الإلكتروني (يتطلب `Bearer`) |
| PATCH | `/api/v1/profile/preferences` | تحديث تفضيل اللغة `{locale}` |
| PUT | `/api/v1/password` | تغيير كلمة المرور `{current_password, password, password_confirmation}` |
| DELETE | `/api/v1/profile` | حذف الحساب نهائياً، يتطلب `{password}` الصحيحة |
| POST | `/api/v1/password/forgot-password` | إرسال رابط استعادة كلمة المرور بالبريد `{email}` |
| POST | `/api/v1/password/reset` | إتمام الاستعادة `{token, email, password, password_confirmation}` |

رابط الاستعادة المُرسَل بالبريد يفتح صفحة الويب (`Auth/ResetPassword`) — تعمل بشكل طبيعي حتى لو فُتحت من متصفح الهاتف؛ ونقطة `POST /password/reset` متاحة أيضاً لعميل يريد معالجة الرمز (token) بنفسه (مثلاً عبر Deep Link يلتقط الرمز من رابط البريد ليكمل العملية داخل التطبيق مباشرة).

> **أمان**: تغيير كلمة المرور عبر `PUT /password` يُبطل تلقائياً كل رموز الوصول (Personal Access Tokens) الأخرى المرتبطة بالحساب — باستثناء الرمز المستخدم لتنفيذ هذا الطلب نفسه، حتى لا يُسجَّل الجهاز الذي غيّر كلمة المرور للتو خروجه من طلبه هو. أي جهاز/توكن آخر (بما فيه توكن مسروق) يفقد الوصول فوراً.

> **ملاحظة**: تسجيل الحساب عبر `POST /auth/register` يحترم كل إعدادات المشرف نفسها التي يحترمها نموذج التسجيل في الويب (`registration_enabled`، `registration_role`، `default_quota_mb`) — تعطيل التسجيل الذاتي من لوحة الإعدادات يمنع إنشاء حسابات عبر الـAPI أيضاً وليس الويب فقط.

### 23.7 الوصول العام (بدون رمز Bearer)

مسارات لا تتطلب مصادقة إطلاقاً — للمشاركة العامة وتصفّح الزوار، مطابقة لمسارات `/s/...` و`/public/...` في الويب:

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/v1/public/shares/short/{code}` | يحوّل رابطاً مختصراً إلى الـtoken الكامل |
| GET | `/api/v1/public/shares/{token}` | بيانات المشاركة (الاسم، الحجم، هل تتطلب كلمة مرور، منتهية؟...) — هذه البيانات ليست سرية حتى لو كانت المشاركة محمية |
| POST | `/api/v1/public/shares/{token}/download` | التنزيل الفعلي؛ إن كانت محمية بكلمة مرور يجب إرسالها `{password}` **في كل طلب** (لا توجد جلسة خادم لتذكّر "فك القفل" كما في الويب) |
| GET | `/api/v1/public/folders` أو `/api/v1/public/folders/{folder}` | تصفّح المجلدات العامة (تتطلب تفعيل "الوصول كزائر" من لوحة الأمان + صلاحية `view`/`download` لدور "زائر" من مصفوفة الصلاحيات) |
| GET | `/api/v1/public/files/{file}/download` و`/thumbnail` | تنزيل/صورة مصغّرة لملف داخل مجلد عام |

> **قيد معروف**: إعداد "إظهار captcha عند التنزيل العام" (`show_captcha_download`) لا يُفرَض على هذه المسارات — تفعيل reCAPTCHA يتطلب واجهة متصفح (widget) لا معنى لها لعميل API عام، تماماً كما أن تسجيل الدخول عبر الـAPI لا يفرض captcha التسجيل. إن كانت حماية captcha ضرورية لحالتك، أبقِ هذه الميزة مقتصرة على الويب فقط (لا تُفعِّل رفع/تنزيل الزوار من الـAPI عندئذ).

### 23.9 لوحة الإدارة عبر API

كل ما تراه لوحة إدارة الويب متاح أيضاً كنقاط JSON تحت `/api/v1/admin/...`، بنفس بوابة "admin" middleware ونفس صلاحيات المدير الفرعي (`can:manage-users`، `can:manage-settings`، `can:manage-translations`، `can:view-statistics`) — أي مدير فرعي لا يملك صلاحية معيّنة يحصل على `403` من نفس النقاط تماماً كما في الويب:

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/v1/admin/dashboard` | إحصائيات عامة + أحدث النشاطات + أكثر المستخدمين استخداماً للمساحة |
| GET/POST/PUT/DELETE | `/api/v1/admin/users[/{user}]` | إدارة المستخدمين الكاملة (يتطلب `can:manage-users`) |
| GET/POST | `/api/v1/admin/settings` | الإعدادات العامة للموقع، بما فيها رفع شعار/صورة ترويسة (`multipart/form-data`) |
| GET/POST | `/api/v1/admin/permissions` | قراءة/تحديث مصفوفة صلاحيات الأدوار |
| GET/POST | `/api/v1/admin/security` | إعدادات الأمان/OAuth/reCAPTCHA |
| POST/DELETE | `/api/v1/admin/security/ip-rules[/{ipRule}]` | قواعد حظر/سماح IP |
| GET/POST | `/api/v1/admin/mail` + `POST .../mail/test` | إعدادات SMTP والإشعارات (كلمة مرور SMTP لا تُعاد أبداً في الاستجابة) |
| GET/POST/DELETE | `/api/v1/admin/translations` | قراءة/تحديث/إعادة تعيين نصوص الترجمة |
| GET | `/api/v1/admin/activity` | سجل النشاط (يتطلب `can:view-statistics`) |
| GET | `/api/v1/admin/analytics?days=30` | بيانات الرسوم البيانية (يتطلب `can:view-statistics`) |

### 23.10 مثال استخدام سريع (curl)

```bash
# تسجيل الدخول والحصول على رمز
TOKEN=$(curl -s -X POST https://your-domain.com/api/v1/auth/login \
  -H "Accept: application/json" -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"secret","device_name":"flutter-app"}' \
  | php -r 'echo json_decode(file_get_contents("php://stdin"))->token;')

# تصفح الجذر
curl -s https://your-domain.com/api/v1/browse -H "Authorization: Bearer $TOKEN"
```

### 23.12 تشغيل الفيديو والصوت (ترجمة، جودات، بث)

مكافئ الـAPI الكامل لمشغّل الوسائط الموصوف في القسم 26، ليستطيع أي عميل خارجي (تطبيق الجوّال Flutter مستقبلاً) بناء نفس تجربة التشغيل: ترجمة قابلة للرفع، جودات فيديو متعددة، وبثّاً يدعم Range للتقديم السريع — بنفس قواعد الصلاحيات المستخدمة في الويب (لا يمكن لمستخدم الوصول لملفات مستخدم آخر، يعود `403`).

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/v1/files/{file}/subtitles` | قائمة ترجمات الفيديو (`id`, `language`, `label`) |
| POST | `/api/v1/files/{file}/subtitles` | رفع ترجمة (`multipart/form-data`: `subtitle` ملف `.srt`/`.vtt`, `language`, `label`) — يُحوَّل SRT إلى WebVTT تلقائياً بكود PHP خالص، يُعيد `{subtitle: {id, language, label}}` |
| GET | `/api/v1/subtitles/{subtitle}` | محتوى الترجمة كنص WebVTT خام (`Content-Type: text/vtt`) — صالح للتغذية المباشرة لأي مشغّل فيديو يدعم WebVTT |
| DELETE | `/api/v1/subtitles/{subtitle}` | حذف ترجمة |
| GET | `/api/v1/files/{file}/preview/{quality}` | بث نسخة بدقة مُحدَّدة بالبكسل (مثلاً `.../preview/480`) بدلاً من الملف الأصلي — يتطلب أن تكون هذه الجودة قد أُنشئت فعلاً (انظر 26.1)، وإلا يعود `404` |

حقلا `video_qualities` و`subtitles_url` مضافان في كائن الملف (`FileResource`) الذي يُعيده `GET /api/v1/browse` وبقية نقاط قوائم الملفات:

```json
{
  "id": 4,
  "mime_type": "video/mp4",
  "video_qualities": [
    { "height": 720, "src": "https://your-domain.com/api/v1/files/4/preview/720" },
    { "height": 480, "src": "https://your-domain.com/api/v1/files/4/preview/480" }
  ],
  "subtitles_url": "https://your-domain.com/api/v1/files/4/subtitles"
}
```

`video_qualities` تكون مصفوفة فارغة `[]` لأي ملف غير فيديو أو لم تُنشأ له جودات بعد (يتطلب تفعيل الإعداد وتوفّر `ffmpeg` على الخادم، انظر 26.3)، و`subtitles_url` تكون `null` لأي ملف غير فيديو — بحيث يمكن لتطبيق الجوّال الاعتماد على وجود القيمة بدل استخدام نوع الملف (MIME) لتحديد إظهار عناصر تحكّم الفيديو.

### 23.13 الفيديو التفاعلي (أسئلة، درجات، تعليقات)

مكافئ الـAPI الكامل لميزة الفيديو التفاعلي الموصوفة في القسم 27 — نفس قواعد التفعيل والصلاحيات والتصحيح على الخادم المستخدمة في الويب. `GET /api/v1/files/{file}/questions` هي أيضاً نقطة النهاية التي يعتمد عليها التطبيق لتخزين نسخة محلية من أسئلة أي فيديو يُنزَّل للعمل بلا إنترنت (انظر القسم 24 أدناه).

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/api/v1/files/{file}/questions` | قائمة أسئلة الفيديو مع خيارات كل سؤال، وحالة إجابة المستخدم الحالي ودرجته التراكمية — يعود `404` إن كانت الميزة معطَّلة من الإعدادات |
| POST | `/api/v1/files/{file}/questions` | إضافة سؤال (`timestamp_seconds`, `question`, `choices[]`, `correct_index`) — يتطلب صلاحية `manage_questions` |
| PUT | `/api/v1/questions/{question}` | تعديل سؤال (نفس حقول الإضافة) |
| DELETE | `/api/v1/questions/{question}` | حذف سؤال |
| POST | `/api/v1/questions/{question}/answer` | تسجيل إجابة (`{choice_id}`) — يعود `{is_correct, correct_choice_id, score}`؛ يعود `422` عند محاولة إجابة نفس السؤال مرة ثانية |
| POST | `/api/v1/files/{file}/questions/import` | استيراد جماعي من ملف JSON أو CSV (`multipart/form-data`: `file`) — يعود `{created, errors[], questions[]}`؛ الأسطر غير الصالحة تُتجاوز وتُذكر في `errors` بدل إفشال الاستيراد بالكامل |
| GET | `/api/v1/questions/import/template` | نموذج CSV جاهز للتنزيل يوضّح الأعمدة المطلوبة |
| GET | `/api/v1/files/{file}/questions/report` | تقرير نتائج مُجمَّع (معدَّل الإجابات الصحيحة لكل سؤال وخيار، ودرجة كل مستخدم أجاب) — يتطلب صلاحية `manage_questions` |
| GET | `/api/v1/files/{file}/comments` | قائمة تعليقات الفيديو |
| POST | `/api/v1/files/{file}/comments` | إضافة تعليق (`body`, `timestamp_seconds` اختياري) — يتطلب صلاحية `comment` |
| DELETE | `/api/v1/comments/{comment}` | حذف تعليق (صاحبه أو صاحب الفيديو) |

مغطّاة باختبارات Feature كاملة في `tests/Feature/Api/InteractiveVideoApiTest.php` (18 اختباراً) بنفس تغطية نظيرتها على الويب، بما فيها الاستيراد الجماعي وتقرير النتائج.

## 24. تطبيق الجوّال (Flutter)

راجع مجلد [`mobile/filenest_app`](mobile/filenest_app) لتطبيق Flutter كامل (تسجيل دخول مع دعم 2FA، تصفّح، رفع/تنزيل، مجلدات، مشاركة، إدارة الحساب الشخصي) يتصل بهذه الواجهة البرمجية مباشرة. تفاصيل البنية والتشغيل موجودة في `mobile/filenest_app/README.md`.

من ميزاته: **الاختيار بين الشبكة المحلية والاستضافة** — شاشة "إعدادات الخادم" في التطبيق تتيح ضبط عنوان خادم على الشبكة المحلية (يعمل بلا إنترنت إطلاقاً طالما الهاتف والخادم على نفس الشبكة) وعنوان استضافة على الإنترنت، مع اختيار تلقائي/محلي فقط/استضافة فقط — تفاصيل كاملة في القسم المخصص من ريدمي التطبيق.

**تنزيل الملفات للعمل بدون إنترنت** — أيقونة تنزيل مستقلة على كل ملف (منفصلة عن المعاينة السريعة عند الضغط عليه)، بدائرة تقدّم فعلية أثناء التنزيل (مع إمكانية الإلغاء) وحفظ دائم في تخزين التطبيق الخاص؛ الملفات المحمَّلة تُفتح لاحقاً دون أي طلب شبكة إطلاقاً، وتظهر مجمَّعة في تبويب "التنزيلات" المستقل.

**الفيديو التفاعلي يعمل بدون إنترنت أيضاً** — مشغّل الوسائط الداخلي يعرض نفس أسئلة/درجات/تعليقات القسم 27؛ تنزيل فيديو للعمل بلا إنترنت يحمّل معه أسئلته تلقائياً، فتُجاب هذه الأسئلة وتُصحَّح محلياً (أو تُعلَّم "بانتظار المزامنة" إن كانت الإجابة الصحيحة غير معروفة محلياً)، ثم تُزامَن مع الخادم في أول اتصال بالإنترنت. لمن يملك صلاحية "إدارة أسئلة الفيديو التفاعلي"، شاشة المشغّل (أونلاين) تتيح أيضاً إضافة/تعديل/حذف الأسئلة يدوياً، استيراداً جماعياً من ملف JSON/CSV، وعرض تقرير نتائج مُجمَّع — نفس الأدوات المتاحة على الويب. التفاصيل الكاملة في ريدمي التطبيق.

**لوحة إدارة كاملة** — لحساب مشرف فقط، تظهر عبر عنصر "الإدارة" في القائمة الجانبية: نظرة عامة، المستخدمون (بحث/إنشاء/تعديل/حذف)، الإعدادات العامة، مصفوفة الصلاحيات، الأمان (Captcha/reCAPTCHA/OAuth/حظر IP)، البريد الإلكتروني (SMTP وإشعارات)، الترجمات، سجل النشاطات، والتحليلات — نفس أقسام لوحة إدارة الويب بالضبط (القسم 22 وما حولها)، كل قسم يظهر فقط إن كانت صلاحية المشرف الفرعية المقابلة له مفعَّلة لهذا الحساب. التفاصيل الكاملة في ريدمي التطبيق.

بُني التطبيق بتنظيم هندسي "حسب الميزة" (كل ميزة في مجلدها الخاص المكتفي بذاته تحت `lib/features/`، ببنية طبقات ثابتة data/state/presentation)، وتنقّل عبر **تبويبات سفلية** (ملفاتي / التنزيلات / المشاركة) و**قائمة جانبية** (الأمان / الحساب / سلة المحذوفات / إعدادات الخادم) بدل تكديس كل الوجهات في شريط علوي واحد، وتصميم بصري مستوحى من تيليجرام (ثيم فاتح/داكن، أيقونات Material حقيقية بلا أي إيموجي). راجع [`mobile/filenest_app/docs/`](mobile/filenest_app/docs/README.md) — ويكي كامل للبنية المعمارية وكيفية إضافة ميزة جديدة، موجَّه للمراجعة والتعديل المستقبلي على كود التطبيق.

> ملاحظة بيئة التطوير الحالية: بيئة العمل التي بُني بها هذا المشروع لا تحتوي على Flutter/Dart SDK مثبّتاً، لذلك كُتب كود التطبيق كاملاً يدوياً باتّباع بنية مشروع Flutter القياسية، لكن لم يُشغَّل عبر `flutter run` أو `flutter test` محلياً في هذه البيئة تحديداً. يُنصح بتشغيل `flutter pub get` ثم `flutter run` على جهاز يملك Flutter SDK للتحقق النهائي قبل الاعتماد في الإنتاج.

## 25. المصادقة الثنائية (2FA)

طبقة حماية إضافية اختيارية لكل مستخدم، مبنية على معيار TOTP القياسي (نفس الآلية المستخدمة في Google Authenticator وAuthy وGoogle Drive/Dropbox وغيرها) عبر حزمة `pragmarx/google2fa` — بدون أي اعتماد على خدمة خارجية أو رسائل SMS.

### 25.1 كيف تعمل

1. من **الملف الشخصي والإعدادات** ← قسم "المصادقة الثنائية (2FA)"، يضغط المستخدم **"تفعيل المصادقة الثنائية"**. أول مرة يُطلب منه فيها تأكيد كلمة المرور الحالية (صفحة "تأكيد كلمة المرور" القياسية في Laravel) إن لم يكن قد فعل ذلك مؤخراً — بحيث لا تكفي جلسة متصفح مسروقة وحدها للعبث بإعداد 2FA. بعدها يُنشئ النظام مفتاحاً سرياً جديداً (غير مُفعَّل بعد) ويعرض رمز QR (يُرسم في المتصفح مباشرة من رابط `otpauth://` عبر مكتبة JS خفيفة، دون أي توليد صور من جهة الخادم) بالإضافة إلى المفتاح كنص لإدخاله يدوياً.
2. يمسح المستخدم الرمز بتطبيق مصادقة على هاتفه، ثم يُدخل رمز التحقق المكوّن من 6 أرقام لتأكيد الإعداد. عند صحة الرمز فقط تُفعَّل الخاصية فعلياً، وتظهر **8 رموز استرداد** لمرة واحدة — يجب حفظها في مكان آمن.
3. من تلك اللحظة، أي تسجيل دخول بكلمة المرور (وليس عبر OAuth) يتوقف بعد صحة كلمة المرور عند صفحة تحقق إضافية تطلب رمز التطبيق (أو أحد رموز الاسترداد كبديل عند فقدان الهاتف). لا تُنشأ جلسة دخول كاملة إلا بعد اجتياز هذه الخطوة.
4. كل رمز استرداد يُستهلك مرة واحدة فقط ويُحذف تلقائياً بعد استخدامه لتسجيل الدخول؛ يمكن توليد مجموعة جديدة بالكامل في أي وقت من نفس الصفحة.
5. تعطيل المصادقة الثنائية يتطلب إعادة إدخال كلمة المرور الحالية للتأكيد.

### 25.2 ملاحظات أمنية وتقنية

- المفتاح السري ورموز الاسترداد مخزّنة في قاعدة البيانات **مشفّرة** (Laravel `encrypted` cast) وليست ظاهرة أبداً في أي استجابة JSON/Inertia تُرسَل للمتصفح (مخفية صراحة على نموذج `User`).
- تسجيل الدخول عبر OAuth (Google/GitHub/LinkedIn) لا يمر بهذه الخطوة الإضافية حالياً — يُعتبر ارتباط الحساب الخارجي نفسه عامل تحقق كافٍ، بنفس النهج المتّبع في معظم الأنظمة المشابهة.
- تُقبل الأكواد ضمن نافذة زمنية صغيرة (± 30 ثانية) للتعامل مع فروقات ساعة الهاتف البسيطة.
- مغطّاة باختبارات Feature كاملة (`tests/Feature/TwoFactorAuthenticationTest.php`): توليد المفتاح، رفض رمز خاطئ، تفعيل بنجاح، تحويل تسجيل الدخول لصفحة التحقق بدل الدخول المباشر، رفض رمز خاطئ في تلك الصفحة، الدخول برمز استرداد ومنع إعادة استخدامه، وتعطيل الخاصية بكلمة مرور خاطئة/صحيحة — بالإضافة إلى تحقّق حي عبر متصفح فعلي يحسب رموز TOTP بشكل مستقل (تطبيق JavaScript منفصل لمعيار RFC 6238) للتأكد من التوافق الفعلي مع أي تطبيق مصادقة قياسي، وليس فقط التوافق الداخلي بين مكوّنات النظام نفسه.

## 26. مشغّل الفيديو والصوت المتقدّم

معاينة ملفات الفيديو والصوت (القسم 20.13) تستخدم الآن مشغّلاً كاملاً بدل عنصر `<video>`/`<audio>` الأساسي، مبني على مكتبتَي [Plyr](https://plyr.io) (فيديو) و[wavesurfer.js](https://wavesurfer.xyz) (صوت) — كلاهما يعملان بالكامل من جهة المتصفح دون أي اعتماد خدمة خارجية وقت التشغيل (حزمة أيقونات Plyr مُضمَّنة محلياً في المشروع بدل تحميلها من `cdn.plyr.io`).

### 26.1 تشغيل الفيديو

- شريط تحكّم كامل: تشغيل/إيقاف، شريط تقدّم، صوت، سرعة التشغيل (0.5x حتى 2x)، ملء الشاشة، وصورة داخل صورة (Picture-in-Picture) على المتصفحات التي تدعمها.
- **الترجمة**: يمكن رفع ملف ترجمة بصيغة `.srt` أو `.vtt` لأي فيديو من داخل نافذة المعاينة نفسها (لغة + اسم للترجمة)، مع إمكانية حذفها لاحقاً. ملفات `.srt` تُحوَّل تلقائياً إلى WebVTT بكود PHP خالص (تحويل الفاصلة العشرية للتوقيت إلى نقطة وإضافة ترويسة `WEBVTT`) — لا حاجة لأي أداة خارجية. تظهر الترجمات كخيارات قابلة للتفعيل/الإيقاف من قائمة "Captions" في المشغّل.
- **قائمة تشغيل**: عند فتح معاينة فيديو (أو صوت) داخل مجلد يحوي ملفات وسائط أخرى من نفس النوع، تظهر قائمة تشغيل جانبية تسمح بالانتقال بينها، مع أزرار السابق/التالي وخيار "تشغيل تلقائي للتالي" عند انتهاء الملف الحالي — تماماً كقوائم التشغيل في يوتيوب.
- **جودات تشغيل متعددة**: عند تفعيل الإعداد (القسم 12) وتوفّر أداة `ffmpeg` على الخادم، يُنشئ الخادم تلقائياً نسخاً بدقات أقل من كل فيديو يُرفع (مثلاً 360/480/720، قابلة للتخصيص)، فتظهر للمستخدم قائمة اختيار الجودة من إعدادات المشغّل (⚙) كما في يوتيوب. عند عدم توفّر `ffmpeg` يستمر تشغيل الملف الأصلي بجودته الوحيدة دون أي تأثير على الرفع أو المعاينة — بنفس نهج التدهور التدريجي الآمن المتّبع في توليد الصور المصغّرة (القسم 22) واستخراج نص المستندات (القسم 21).

### 26.2 تشغيل الصوت

ملفات الصوت تُعرض بموجة صوتية تفاعلية (Waveform) على طراز SoundCloud بدلاً من شريط تقدّم بسيط، مع أزرار تشغيل/إيقاف، سرعة تشغيل، وتحكّم بالصوت — الموجة تُرسَم بالكامل داخل المتصفح (WebAudio) دون أي معالجة على الخادم.

### 26.3 التفاصيل التقنية

- **الجداول**: `subtitles` (ترجمات كل فيديو) و`video_qualities` (نسخ الجودة المُنشأة) — كلاهما مرتبط بجدول `files` بحذف تسلسلي (`cascadeOnDelete`)، وبايتات الملفات على القرص تُحذف تلقائياً عند حذف الملف نهائياً (وليس فقط عند إفراغه إلى سلة المحذوفات).
- **الخدمات**: `App\Services\SrtToVttConverter` (تحويل نصّي خالص)، `App\Services\VideoTranscoder` (يتحقق من توفّر `ffmpeg` بنفس طريقة `ThumbnailGenerator` قبل أي محاولة تحويل، ولا يرفع استثناءً أبداً عند غيابه).
- **المهمة المُجدولة**: `App\Jobs\TranscodeVideoQualities` تُشغَّل تلقائياً بعد اكتمال أي رفع فيديو (رفع عادي أو من رابط خارجي)، بنفس أسلوب `GenerateThumbnail`/`ExtractFileText` الحالي.
- **الإعدادات** (`/admin/settings`): تفعيل/تعطيل إنشاء الجودات المتعددة، وقائمة الدقات المستهدفة بالبكسل.
- **متاحة أيضاً عبر REST API** (القسم 23.12) بنفس القواعد والصلاحيات — تطبيق الجوّال Flutter (القسم 24) لا يستخدم هذه النقاط بعد، لكنها جاهزة للربط المستقبلي دون أي تعديل إضافي على الخادم.
- مغطّاة باختبارات Feature كاملة على الويب والـAPI (`tests/Feature/SubtitleTest.php`, `tests/Feature/VideoQualityTest.php`, `tests/Feature/Api/SubtitleApiTest.php`, `tests/Feature/Api/VideoQualityApiTest.php`): تحويل SRT إلى VTT، رفع/عرض/حذف الترجمات ومنع الوصول لملفات مستخدم آخر، تخطّي التحويل عند التعطيل، عدم رفع أي استثناء عند غياب `ffmpeg` (اختبار غير مرتبط ببيئة تشغيل معيّنة، على غرار اختبارات `ThumbnailGenerator`)، حذف بايتات الترجمة/الجودة من القرص عند الحذف النهائي للملف، وتحقّق حي عبر `curl` ضد خادم فعلي لمسارات الـAPI (تسجيل، رفع ترجمة، جلب محتوى WebVTT، بث جودة محددة، ورفض وصول مستخدم آخر بـ 403).

> ملاحظة بيئة التطوير الحالية: أداة `ffmpeg` غير مثبّتة في بيئة العمل التي بُنيت بها هذه الميزة، لذلك تحقّق مسار "عدم توفر الأداة" (تخطّي التحويل دون أخطاء) حياً عبر خادم فعلي، بينما تحقّق إنتاج نسخ فعلية بجودات مختلفة يتطلب خادماً يملك `ffmpeg` مثبّتاً فعلياً.

## 27. الفيديو التفاعلي (أسئلة، درجات، تعليقات)

ميزة اختيارية بالكامل — معطَّلة افتراضياً حتى يفعّلها مشرف من **الإعدادات**. عند التفعيل، يمكن لمن يملك صلاحية "إدارة أسئلة الفيديو التفاعلي" إضافة أسئلة اختيار من متعدد تظهر وتوقف تشغيل أي فيديو عند لحظة محدَّدة منه، وتُسجَّل درجة كل مشاهد تلقائياً.

### 27.1 التفعيل

من **الإعدادات → الفيديو التفاعلي**، فعِّل خانة "تفعيل الأسئلة التفاعلية داخل الفيديو". عند التعطيل يختفي زر إدارة الأسئلة تماماً وتُشغَّل كل الفيديوهات بلا توقّف، دون حذف أي أسئلة أو درجات محفوظة مسبقاً — إعادة التفعيل تُعيدها فوراً كما كانت.

### 27.2 إضافة الأسئلة

من نافذة معاينة أي فيديو، قسم "الأسئلة التفاعلية" (يظهر فقط لمن يملك صلاحية الإدارة) يتيح:

- إضافة سؤال جديد: نص السؤال، الثانية التي يظهر عندها (زر "استخدام الوقت الحالي" يأخذها من نقطة التشغيل الحالية)، من خيارين إلى ستة خيارات نصية، وتحديد الخيار الصحيح.
- تعديل أو حذف أي سؤال موجود من نفس القائمة.
- **استيراد جماعي**: زر "استيراد أسئلة من ملف (JSON/CSV)" يرفع ملفاً يحتوي على عدة أسئلة دفعة واحدة، مع رابط "تنزيل نموذج CSV" يوضّح الأعمدة المطلوبة. صيغة JSON: مصفوفة من كائنات `{timestamp_seconds, question, choices: [...], correct_index}`؛ صيغة CSV: عمود `timestamp_seconds`، `question`، أعمدة `choice_1..choice_N`، ثم `correct_index`. أي سطر غير صالح (سؤال فارغ، رقم إجابة خارج نطاق الخيارات، إلخ) يُتجاوز ويُذكر في رسالة النتيجة بدل إفشال الاستيراد بالكامل؛ إن لم ينجح أي سطر يُرفض الملف كاملاً برسالة خطأ واضحة.

### 27.3 أثناء المشاهدة

- عند وصول الفيديو إلى لحظة سؤال لم يُجب عليه المشاهد بعد، يتوقّف تلقائياً وتظهر نافذة السؤال فوقه — لا يمكن إكمال المشاهدة دون اختيار إجابة.
- **لا يمكن تخطّي سؤال بالسحب للأمام على شريط التقدّم**: إذا حاول المستخدم السحب إلى ما بعد سؤال لم يُجب عليه، يُعاد المؤشر تلقائياً إلى لحظة ذلك السؤال.
- بعد الإرسال، تظهر النتيجة (صحيحة/خاطئة) فوراً، ثم زر "متابعة المشاهدة" يُكمل التشغيل. الإجابة نهائية — لا يمكن تغييرها لاحقاً بإعادة مشاهدة نفس اللحظة.
- درجة المشاهد التراكمية ("درجتك: X من Y") تظهر أعلى نافذة المعاينة بمجرد الإجابة على سؤال واحد على الأقل.

### 27.4 تقرير النتائج

من نفس قسم "الأسئلة التفاعلية"، زر "تقرير النتائج" (يظهر عند وجود سؤال واحد على الأقل) يعرض:

- عدد المشاهدين الذين أجابوا ومتوسط درجاتهم.
- لكل سؤال: عدد الإجابات الكلي، ونسبة اختيار كل خيار كشريط تقدّم — يُبرَز الخيار الصحيح باللون الأخضر، ما يساعد على اكتشاف خيار مُشتِّت يُربك أغلب المشاهدين.
- جدول بدرجة كل مستخدم أجاب (عدد الإجابات الصحيحة من إجمالي الأسئلة ونسبتها)، مرتّب تنازلياً حسب الدرجة.

ملاحظة معمارية: نظام الصلاحيات الحالي مبني على ملكية الملف — فقط مالك الفيديو أو أحد المشرفين يمكنه أصلاً مشاهدته والإجابة على أسئلته عبر هذه المسارات، لذا "عدد المشاهدين" في التقرير يعكس هؤلاء تحديداً (وليس أي زائر عام).

### 27.5 التعليقات

قسم تعليقات أسفل كل فيديو (لمن يملك صلاحية "التعليق على الفيديوهات"، مفعَّلة افتراضياً لمعظم الأدوار): يمكن ربط أي تعليق اختيارياً بلحظة معيّنة من الفيديو (خانة "ربط التعليق بلحظة ... الحالية")، والنقر على وقت أي تعليق مربوط بلحظة يُعيد التشغيل إلى تلك اللحظة مباشرة. صاحب التعليق يحذف تعليقه، وصاحب الفيديو يحذف أي تعليق على فيديوهاته.

### 27.6 التفاصيل التقنية

- **الجداول**: `video_questions`، `video_question_choices`، `video_question_answers` (إجابة واحدة نهائية لكل مستخدم لكل سؤال، بقيد `unique` على `(video_question_id, user_id)`)، و`video_comments` — جميعها مرتبطة بجدول `files` بحذف تسلسلي، بنفس نهج `subtitles`/`video_qualities` (القسم 26.3).
- **الصلاحيات**: `manage_questions` (إضافة/تعديل/حذف الأسئلة) و`comment` (نشر تعليق) — قابلتان للتخصيص لكل دور من **الإدارة → الصلاحيات**، بنفس آلية بقية الصلاحيات في النظام.
- **إخفاء الإجابة الصحيحة**: نقطة `GET /files/{file}/questions` لا تُرسل أي إشارة للإجابة الصحيحة إلى مشاهد عادي — فقط من يملك صلاحية `manage_questions` يراها (لعرضها عند التعديل). التصحيح الفعلي يحدث بالكامل على الخادم عند إرسال الإجابة.
- **متاحة أيضاً عبر REST API** بنفس المسارات والقواعد (انظر القسم 23.13)، وتطبيق Flutter يستخدمها فعلياً لعرض الأسئلة/التعليقات، لإدارتها (إضافة/تعديل/حذف/استيراد جماعي/تقرير نتائج) لمن يملك الصلاحية، وللعمل بلا إنترنت (انظر القسم 24).
- **تقرير النتائج** (`GET /files/{file}/questions/report`) محسوب بالكامل عند الطلب من جدولي `video_question_answers`/`video_question_choices` مباشرة (لا جدول تجميع منفصل)، ومحمي بنفس شرطي `update` على الملف وصلاحية `manage_questions`.
- مغطّاة باختبارات Feature كاملة (`tests/Feature/InteractiveVideoTest.php`): التعطيل يمنع الوصول تماماً، منع من لا يملك صلاحية الإدارة من إنشاء أسئلة، إخفاء/إظهار الإجابة الصحيحة حسب الصلاحية، تسجيل الإجابة وتحديث الدرجة، منع إجابة سؤال مرتين، منع الوصول لأسئلة/تعليقات ملف مستخدم آخر، نشر/حذف التعليقات مع التحقق من الصلاحية، الاستيراد الجماعي (JSON وCSV، تجاوز الأسطر غير الصالحة، رفض الملف بلا أسطر صالحة، والتحقق من صلاحية الاستيراد)، وتقرير النتائج (تجميع صحيح لكل سؤال ومستخدم، والتحقق من الصلاحية والتفعيل).

## 28. قوائم التشغيل (Playlists)

قوائم تشغيل مُسمّاة يُنشئها المستخدم ويرتّب عناصرها بنفسه، لملفات الفيديو والصوت — على عكس الطابور التلقائي الذي يبنيه المشغّل عند فتح أي ملف وسائط (كل ملفات نفس المجلد من نفس النوع)، تبقى قائمة التشغيل محفوظة باسمها وترتيبها إلى أن يعدّلها صاحبها.

### 28.1 الاستخدام

- من القائمة الجانبية، رابط "قوائم التشغيل" يفتح صفحة بكل قوائم المستخدم (صورة العنصر الأول وعدد العناصر لكل قائمة)، مع زر "قائمة جديدة".
- فتح أي قائمة يعرض عناصرها بترتيبها، مع إمكانية إعادة الترتيب بالسحب والإفلات، إعادة تسمية القائمة، حذف عنصر أو حذف القائمة بالكامل، وتشغيل عنصر بعينه أو "تشغيل الكل" من البداية.
- من قائمة إجراءات أي ملف فيديو/صوت في متصفح الملفات، خيار "إضافة إلى قائمة تشغيل" يفتح نافذة تعرض كل قوائم المستخدم (وتُميّز ما يحتوي الملف بالفعل)، مع خيار إنشاء قائمة جديدة وإضافة الملف إليها مباشرة.
- لا يمكن إضافة نفس الملف مرتين إلى نفس القائمة، ولا إضافة ملف غير فيديو/صوت.

### 28.2 التفاصيل التقنية

- **الجداول**: `playlists` (اسم + مالك) و`playlist_items` (ملف + ترتيب داخل القائمة، بقيد `unique` على `(playlist_id, file_id)` يمنع تكرار نفس الملف).
- **الصلاحيات**: مبنية على الملكية فقط (مثل `SharePolicy`) — صاحب القائمة أو أي مشرف يمكنه عرضها/تعديلها/حذفها، ولا أحد غيرهما.
- **متاحة أيضاً عبر REST API** بنفس المسارات والقواعد (`Api\V1\PlaylistController`، انظر القسم 23)، وتطبيق Flutter يستخدمها فعلياً بواجهة مطابقة للويب (انظر القسم 24).
- نقطة `GET /playlists/picker` مخصّصة لنافذة "إضافة إلى قائمة تشغيل" فقط: ترجع كل قوائم المستخدم مع علامة `contains_file` لكل قائمة بدل تحميل صفحة كاملة.
- مغطّاة باختبارات Feature كاملة على الويب والـAPI (`tests/Feature/PlaylistTest.php`, `tests/Feature/Api/PlaylistApiTest.php`): إنشاء قائمة (مع/بدون ملف أولي)، إضافة/إزالة عنصر، منع إضافة ملف غير وسائط أو مكرر، إعادة الترتيب، إعادة التسمية، الحذف، نقطة الـpicker، ومنع أي مستخدم من الوصول إلى قائمة مستخدم آخر.

## 29. تعدد اللغات والمظهر الليلي/النهاري

### 29.1 تعدد اللغات

كانت البنية التحتية للترجمة موجودة أصلاً (لغة محفوظة لكل مستخدم، تبديل `dir`/`lang` بين RTL/LTR، محرر ترجمات إداري، ملفات `lang/ar.json`/`lang/en.json`) لكن لم تكن أي واجهة Vue تستخدمها فعلياً — كل نص كان عربياً ثابتاً داخل القالب. أضيف composable خفيف `useTrans()` (`resources/js/Composables/useTrans.js`) يقرأ الخاصية المشتركة `translations` ويُستخدم بالشكل `t('key', 'النص العربي الافتراضي')` — تمرير النص العربي الحالي كقيمة احتياطية يعني عدم تغيّر أي شيء للمستخدم العربي إلى أن يُضاف المفتاح فعلياً إلى `lang/en.json` (أو يُخصَّص من لوحة الإدارة).

**مفعّلة بالكامل** (نص + اتجاه): الهيكل العام (`AppLayout`، `AdminLayout`، `GuestLayout`)، صفحات تسجيل الدخول/التسجيل، لوحة الملفات الرئيسية، المشاركة، سلة المحذوفات، قوائم التشغيل، والملف الشخصي/الإعدادات، بالإضافة إلى كل نوافذ الإجراءات المنبثقة (مجلد جديد، إعادة تسمية، نقل، مشاركة، إضافة إلى قائمة تشغيل).

من **الملف الشخصي → تفضيلات الواجهة**، تغيير اللغة يُحدّث فوراً اتجاه الصفحة (`dir`) ولغة HTML، إلى جانب كل النصوص المفتاحية عبر التطبيق.

**لم تُحوَّل بعد** (تبقى عربية حتى لو بدّل المستخدم اللغة، وهي المهمة التالية): لوحة الإدارة بكامل صفحاتها (المستخدمون، الإعدادات، الصلاحيات، الأمان، البريد، التحليلات، سجل النشاط)، نافذة معاينة الفيديو/الصوت الكاملة (الأسئلة التفاعلية، التعليقات، الترجمات)، صفحة التحقق بخطوتين، وصفحات تصفّح المجلدات العامة للزوار. رسائل الخادم (كالنجاح بعد الحذف) لا تزال عربية أيضاً بما أنها نصوص حرفية داخل المتحكمات وليست عبر `__()`.

### 29.2 المظهر الليلي/النهاري

مبني من الصفر (لم يكن موجوداً إطلاقاً): `tailwind.config.js` يستخدم `darkMode: 'class'`، ومتجر تفاعلي بسيط `useTheme()` (`resources/js/Composables/useTheme.js`) يحفظ الاختيار (فاتح/داكن/حسب النظام) في `localStorage` ويطبّق كلاس `dark` على `<html>`، مع سكربت مضمّن في `app.blade.php` يطبّق القيمة المحفوظة قبل أول رسم للصفحة لتفادي وميض المظهر الخاطئ. زر تبديل المظهر (`ThemeToggle.vue`) موجود في رأس الصفحة بكل من `AppLayout` و`AdminLayout`.

أغلب مكوّنات Breeze الأساسية (Modal، Dropdown، الأزرار، الحقول) كانت تحتوي فعلاً على كلاسات `dark:` جاهزة من القالب الافتراضي — كانت خاملة فقط قبل تفعيل `darkMode: 'class'`، لذا حصلت صفحات الدخول وكل نافذة مبنية عليها على وضع ليلي كامل شبه مجاناً.

### 29.3 تطبيق الجوّال (Flutter)

نفس الميزة مطبَّقة أيضاً على تطبيق Flutter (لغة عربية/إنجليزية فعلية مع اتجاه RTL/LTR حقيقي عبر `flutter_localizations`، ومظهر فاتح/داكن/حسب النظام قابل للتبديل يدوياً) — راجع قسم "تعدد اللغات والمظهر الليلي/النهاري" في `mobile/filenest_app/README.md` للتفاصيل الكاملة ونطاق التغطية الحالي.
